Social Network & Factions — จากความสัมพันธ์สู่กิลด์และอาณาจักร

**เกม:** พงศาวดารใต้ดวงดาว  
**บริบท:** โลกออนไลน์ร่วมกันที่ NPC สร้างชีวิต องค์กร ชุมชน และประวัติศาสตร์เอง  
**เวอร์ชัน:** 0.1 — ข้อเสนอสำหรับออกแบบต้นแบบและขยายสเกล  
**หลักการ:** ความสัมพันธ์ระดับบุคคลเป็นฐานให้เกิดองค์กร และองค์กรที่มีทรัพยากร/ความชอบธรรมเพียงพอจึงค่อยพัฒนาเป็นสถาบันหรืออาณาจักร

**ภาพรวม:** NPC สร้างความสัมพันธ์จากเหตุการณ์จริง ความสัมพันธ์เชื่อมเป็นเครือข่าย กลุ่มคนที่มีเป้าหมายร่วมกันอาจตั้งองค์กร และองค์กรที่ควบคุมพื้นที่ มีทรัพยากร ระบบบริหาร และความยอมรับจากประชาชนจึงอาจกลายเป็นรัฐหรืออาณาจักร

## 1. เป้าหมายของระบบ

ระบบต้องทำให้ผู้เล่นเห็นความเปลี่ยนแปลงหลายระดับที่ต่อเนื่องกัน:

1.  **บุคคล:** ใครไว้ใจ ชอบ เคารพ หรือมีข้อขัดแย้งกับใคร เพราะเหตุใด

2.  **ครัวเรือน:** คู่ชีวิต ครอบครัว ผู้ดูแล ลูกศิษย์ และผู้สืบทอดมีผลต่อการตัดสินใจอย่างไร

3.  **องค์กร:** กิลด์/สมาคมเกิดจากความต้องการร่วม มีสมาชิก กฎ ทรัพยากร และความขัดแย้งภายใน

4.  **ชุมชนและฝ่ายอำนาจ:** หมู่บ้านหรือกลุ่มอาชีพมีผลประโยชน์/ความต้องการร่วม และเจรจากับองค์กรอื่นได้

5.  **รัฐ/อาณาจักร:** การรวมศูนย์อำนาจเกิดได้เมื่อมีประชากร รายได้ ความปลอดภัย การบริหาร และความชอบธรรมรองรับ

6.  **ประวัติศาสตร์:** การแต่งงาน การก่อตั้งกิลด์ การเปลี่ยนผู้นำ หรือการเกิดอาณาจักรถูกบันทึกและส่งผลต่อรุ่นถัดไป

ระบบไม่ควรสร้างอาณาจักรเป็นเพียงแถบสีบนแผนที่ แต่ต้องแสดงว่าใครสนับสนุน ใครได้/เสียประโยชน์ และรัฐนั้นดูแลพื้นที่ได้จริงหรือไม่

## 2. หลักการออกแบบ

### 2.1 ความสัมพันธ์มาจากเหตุการณ์ ไม่ใช่บทบาทที่ล็อกไว้

NPC อาจเป็นเพื่อน คู่แข่ง ลูกศิษย์ หรือศัตรูได้จากการพบปะ การช่วยเหลือ การผิดสัญญา และผลประโยชน์ ไม่ควรกำหนดความสัมพันธ์ทั้งหมดด้วยสคริปต์ก่อนเริ่มโลก

### 2.2 ความสัมพันธ์เป็นหลายมิติและมีทิศทาง

คนสองคนอาจรู้สึกไม่เท่ากัน เช่น A เคารพ B แต่ B ไม่ไว้ใจ A จึงไม่ใช้ค่า “ความสัมพันธ์” เลขเดียวแทนทุกอย่าง

### 2.3 องค์กรมีเป้าหมายและข้อจำกัด

กิลด์หรืออาณาจักรต้องมีสมาชิก งบประมาณ การบริหาร และผลประโยชน์ร่วม ไม่เกิดจากจำนวน NPC ถึงเกณฑ์เพียงอย่างเดียว

### 2.4 ความยินยอมและเจตจำนงของ NPC

ความสัมพันธ์คู่ชีวิต/การแต่งงานต้องเกิดจากการตัดสินใจของตัวละครผู้ใหญ่ที่มีความสมัครใจ ไม่ใช่ผู้เล่นเลือกจับคู่หรือใช้แต้มบังคับ

### 2.5 โครงสร้างใหญ่มีทั้งประโยชน์และต้นทุน

กิลด์ช่วยประสานงานแต่มีค่าใช้จ่ายและการเมืองภายใน อาณาจักรเพิ่มความปลอดภัย/โครงสร้างพื้นฐานแต่ต้องเก็บภาษี จัดการข้อขัดแย้ง และรักษาความชอบธรรม

### 2.6 สเกลด้วยการรวมข้อมูล ไม่ใช่จำลองทุกคู่ทุกคน

จำลองความสัมพันธ์ละเอียดเฉพาะเครือข่ายที่มีความหมาย ส่วนประชากรทั่วไปเป็นกลุ่ม/สถิติ และคำนวณการเปลี่ยนแปลงเมื่อเกิดเหตุการณ์

## 3. โมเดล Social Network

### 3.1 กราฟสังคม

ใช้กราฟที่มี:

- **โหนดบุคคล:** NPC รายบุคคล

- **โหนดครัวเรือน:** ครอบครัว/กลุ่มผู้ดูแล/ผู้พึ่งพิง

- **โหนดองค์กร:** กิลด์ สมาคม หน่วยยาม กลุ่มพ่อค้า

- **โหนดชุมชน/รัฐ:** หมู่บ้าน เมือง อาณาจักร

- **เส้นเชื่อม:** ความสัมพันธ์หรือการเป็นสมาชิก พร้อมทิศทางและสถานะ

กราฟไม่จำเป็นต้องแสดงทุกเส้นบนหน้าจอ ผู้เล่นเลือกตัวละคร/องค์กรตั้งต้นแล้วเปิดดูความสัมพันธ์ที่เกี่ยวข้อง

### 3.2 ประเภทเส้นเชื่อมระหว่างบุคคล

| ประเภท                  | ทิศทาง               | ใช้กับพฤติกรรม                        |
|-------------------------|---------------------|------------------------------------|
| ความไว้ใจ (Trust)        | มีทิศทาง              | แบ่งข้อมูล ขอความช่วยเหลือ ยอมเสี่ยงร่วมกัน |
| ความชอบ/ผูกพัน (Affinity) | มีทิศทาง              | เลือกใช้เวลา อยู่ร่วมกลุ่ม หรือดูแลกัน       |
| ความเคารพ (Respect)     | มีทิศทาง              | ยอมรับการนำ/คำแนะนำ/ความเชี่ยวชาญ     |
| ความคับข้องใจ (Grievance) | มีทิศทาง              | ปฏิเสธ ร้องเรียน ถอนตัว หรือโต้แย้ง       |
| ภาระ/บุญคุณ (Obligation)  | มีทิศทาง              | ชดใช้ ช่วยเหลือ หรือทำตามคำมั่นบางอย่าง   |
| ความใกล้ชิด (Familiarity) | โดยทั่วไปสมมาตร       | รับรู้ประวัติ/นิสัยของอีกฝ่าย               |
| ครอบครัว/ผู้ดูแล            | มีชนิดและสถานะ        | การดูแล มรดก การอยู่ครัวเรือนร่วมกัน      |
| ครู–ลูกศิษย์                | มีทิศทาง/บทบาท        | การถ่ายทอดทักษะ ความรู้ และเครือข่าย     |
| คู่ชีวิต/คู่สมรส              | เชื่อมสองทาง แต่มีสถานะ | ครัวเรือน เป้าหมายร่วม และมรดก         |

### 3.3 ช่วงค่า

ค่าความสัมพันธ์หลักใช้ 0–100 หรือ -100 ถึง +100 ตามความหมาย:

- Trust, Affinity, Respect, Familiarity: 0–100

- Grievance: 0–100 โดยค่ายิ่งสูงคือความคับข้องใจยิ่งมาก

- Obligation: 0–100 พร้อมเหตุผล/ภาระที่ผูกไว้

UI แสดงเป็นระดับ เช่น ต่ำ/ปานกลาง/สูง และตัวอย่างเหตุการณ์ ไม่จำเป็นต้องเปิดค่าตัวเลขละเอียดทั้งหมด

### 3.4 การเปลี่ยนค่า

ความสัมพันธ์เปลี่ยนจาก event ที่เกี่ยวข้องโดยตรง:

> relationship_delta = event_impact
>
> × personal_relevance
>
> × source_credibility
>
> × trait_sensitivity

จากนั้น clamp ตามช่วงและใช้ diminishing returns เมื่อค่าความสัมพันธ์ใกล้สุดขอบ เพื่อไม่ให้เหตุการณ์เล็กครั้งเดียวเปลี่ยนศัตรูเป็นเพื่อนสนิททันที

ตัวอย่าง event impact:

- ช่วยชีวิต: Trust + สูง, Affinity + ปานกลาง, Obligation + เล็กน้อยถึงสูงตามการตีความ

- แบ่งรางวัลไม่เป็นธรรม: Trust -, Grievance +

- ทำงานร่วมกันสำเร็จ: Respect +, Familiarity +

- ผิดสัญญาซ้ำ: Trust ลดและ Grievance เพิ่มมากกว่าครั้งแรก

### 3.5 การเสื่อม/คงอยู่ของความสัมพันธ์

- ความคุ้นเคยและความชอบอาจลดช้าเมื่อไม่พบกัน

- ความไว้ใจที่เกิดจากเหตุการณ์รุนแรงลดช้ากว่าความคุ้นเคย

- ความคับข้องใจไม่หายเพียงเพราะเวลา แต่ลดได้จากการขอโทษ ชดใช้ หรือเปลี่ยนพฤติกรรม

- ความสัมพันธ์ครอบครัว/คู่ชีวิตไม่ลบอัตโนมัติ แต่เปลี่ยนสถานะได้จากเหตุการณ์จริง

- พงศาวดารเก็บข้อเท็จจริงถาวร แม้ความทรงจำส่วนตัวจะจางลง

## 4. การพบปะ การสร้างความสัมพันธ์ และการแพร่ข่าว

### 4.1 โอกาสพบปะ

NPC มีโอกาสรู้จักกันจาก:

- อยู่พื้นที่เดียวกันและมีกิจกรรมร่วม

- งาน/กิลด์/ตลาด/การเดินทาง

- ความสัมพันธ์ผ่านเพื่อนหรือครอบครัว

- ภารกิจและเหตุการณ์ชุมชน

- ข่าวสารที่ส่งผ่านเครือข่าย

ไม่สร้างความสัมพันธ์เชิงลึกกับทุกคนที่พบโดยอัตโนมัติ การพบปะครั้งแรกเพิ่ม Familiarity เล็กน้อย ส่วนความไว้ใจ/ผูกพันต้องอาศัยเหตุการณ์

### 4.2 การส่งต่อข่าวสาร

ข่าวเดินทางผ่านคนและองค์กร มี:

> Rumor = {claim, source_id, confidence, created_at, last_heard_at,
>
> route_or_network_path, privacy_level}

- ข่าวยืนยันอาจถูกบิดเบือนเล็กน้อยเมื่อต่อหลายทอด

- ความไว้ใจต่อผู้ส่งและทักษะของผู้รับมีผลต่อความเชื่อ

- ข่าวลือที่หมดอายุลดความสำคัญ

- ข้อมูลลับไม่แพร่ไปทั่วโลกโดยทันที

- การแพร่ข่าวมีผลต่อชื่อเสียง การรับสมาชิก และการเมืองขององค์กร

### 4.3 เครือข่ายอิทธิพลทางสังคม

NPC มี “ความน่าเชื่อถือทางสังคม” ตามประสบการณ์ ความสัมพันธ์ และบทบาท ไม่ใช่แค่ค่าชื่อเสียงหนึ่งค่า คนที่มี respect สูงในกิลด์อาจโน้มน้าวสมาชิกกิลด์ได้ แต่ไม่จำเป็นต้องมีผลกับชาวนาในอีกเมือง

การแพร่ความคิดเห็นคำนวณเฉพาะเครือข่ายที่มีช่องทางติดต่อจริง และมีโอกาสปฏิเสธ/ตีความต่าง ไม่ใช้การส่งต่อแบบ contagion อัตโนมัติทุกคนเชื่อเหมือนกัน

## 5. ครัวเรือน คู่ชีวิต และการแต่งงาน

### 5.1 หลักการ

การเป็นคู่ชีวิต/แต่งงานเป็นความสัมพันธ์ระหว่าง NPC ผู้ใหญ่ที่มีความสมัครใจและความเข้ากันได้ ไม่ใช่รางวัลหรือคำสั่งของผู้เล่น และไม่จำเป็นต้องนำไปสู่การมีบุตร

ความสัมพันธ์อาจมีสถานะหลายแบบตามธรรมเนียมของโลก:

- รู้จัก/สนใจ

- กำลังคบหา/สร้างความไว้ใจ

- คู่ชีวิตหรือครัวเรือนร่วม

- สมรส/ผูกพันตามกฎหมายหรือพิธีของชุมชน

- แยกกันอยู่/ยุติความสัมพันธ์

- คู่ชีวิตที่เสียชีวิต/เป็นหม้าย

### 5.2 การประเมินความเข้ากันได้

NPC พิจารณา:

- ความไว้ใจและความชอบต่อกัน

- เป้าหมายชีวิตและค่านิยม

- ความพร้อมด้านบ้าน/รายได้/ภาระดูแล

- ความปลอดภัยและความมั่นคงของชุมชน

- ความต้องการมีครัวเรือนร่วมกัน

- ความคาดหวังของครอบครัว/สังคม หากเกี่ยวข้อง

- ความขัดแย้งหรือประวัติผิดสัญญา

> partnership_utility = mutual_affinity
>
> \+ mutual_trust
>
> \+ shared_goal_fit
>
> \+ household_readiness
>
> \+ relationship_history
>
> \- unresolved_grievance
>
> \- coercion_or_dependency_risk

ความสมัครใจเป็นเงื่อนไขบังคับ ไม่ใช่คะแนนที่ชดเชยได้ด้วยทรัพย์สินหรือชื่อเสียง

### 5.3 การสร้างความสัมพันธ์เป็นขั้น

1.  พบปะและเพิ่มความคุ้นเคย

2.  เกิดเหตุการณ์สร้างความไว้ใจ/ความสนใจ

3.  แต่ละฝ่ายประเมินความต้องการและความเข้ากันได้

4. มีคำชวน/การตอบรับที่ NPC เป็นผู้เริ่มหรือมีส่วนตัดสินใจ

5. สร้างครัวเรือนร่วม/พิธีตามบริบท

6. เป้าหมายและทรัพย์สินบางส่วนอาจผูกกัน แต่ยังมีทรัพย์สินส่วนตัว

7. ความสัมพันธ์เปลี่ยนได้จากเหตุการณ์ ระยะห่าง และการกระทำ ไม่คงที่ตลอดไป

### 5.4 ความหลากหลายของครัวเรือน

ครัวเรือนอาจเป็นคู่ชีวิต ครอบครัวหลายรุ่น ผู้ปกครองคนเดียว ครอบครัวอุปถัมภ์ หรือกลุ่มสมาชิกที่เลือกอยู่ร่วมกัน ระบบไม่ควรยึดรูปแบบครัวเรือนเดียวเป็นข้อกำหนดของการสืบทอด

### 5.5 ความขัดแย้งและการเลิกรา

ความขัดแย้งเกิดจากการผิดสัญญา ความไม่ปลอดภัย การแยกกันอยู่ หรือเป้าหมายที่ขัดกัน NPC อาจพยายามปรับความเข้าใจก่อนยุติความสัมพันธ์ หากมีการเลิกรา:

- แบ่งทรัพย์สินตามเจ้าของ/ข้อตกลงในโลก

- รักษาความสัมพันธ์ผู้ดูแล/ผู้พึ่งพิงแยกจากสถานะคู่ชีวิต

- สร้างผลต่อความทรงจำและเครือข่าย

- ไม่ลงโทษผู้เล่นที่จับตามองตัวละครใดตัวละครหนึ่ง

## 6. การตั้งกิลด์และองค์กร NPC

### 6.1 เงื่อนไขการก่อตั้ง

กิลด์เกิดเมื่อมีความต้องการร่วมที่ต่อเนื่องและมีผู้ก่อตั้ง/ทรัพยากรรองรับ ไม่เกิดจากสุ่มชื่อองค์กรขึ้นมา

เงื่อนไขตั้งต้นอาจประกอบด้วย:

- NPC ผู้ก่อตั้งอย่างน้อย 3 คนที่มีเป้าหมายร่วม

- มีผู้จัดการ/ผู้นำที่สมาชิกยอมรับ

- มีสถานที่ตั้งหรือช่องทางประสานงาน

- มีเงินเริ่มต้น/ทุนหมุนเวียน หรือทรัพยากรที่สมาชิกสมทบ

- มีปัญหาหรือบริการที่สมาชิกต้องการ เช่น รับงาน คุ้มกันเส้นทาง ฝึกช่าง หรือค้าส่ง

- ชุมชนมีขนาดและความต้องการพอรองรับองค์กร

จำนวนสมาชิกและทุนเป็นค่าตั้งต้นสำหรับต้นแบบ ไม่ใช่ข้อกำหนดแข็งตาย

### 6.2 วงจรชีวิตกิลด์

1. **กลุ่มไม่เป็นทางการ:** เพื่อน/คนทำงานร่วมกัน แบ่งข้อมูลและทรัพยากรเป็นครั้งคราว

2. **ชมรม/สมาคมตั้งต้น:** มีเป้าหมายร่วมและกติกาง่าย ๆ

3. **กิลด์จดทะเบียน:** มีผู้นำ คลัง งบ และสิทธิ์รับงาน/บริการ

4. **องค์กรเติบโต:** มีสาขา งานประจำ ระบบฝึกคน และความสัมพันธ์กับสถาบันอื่น

5. **องค์กรแตกแขนง/รวม/เสื่อม:** สมาชิกแยกกลุ่ม ถูกดูดซึม รวมกับองค์กรอื่น หรือปิดกิจการ

### 6.3 โครงสร้างสมาชิก

บทบาททั่วไป:

- ผู้ก่อตั้ง/ผู้นำ

- ผู้ดูแลการเงินหรือคลัง

- ผู้จัดงาน/รับภารกิจ

- ผู้เชี่ยวชาญ/ครูฝึก

- สมาชิกประจำ

- ลูกมือ/ผู้สมัคร

บทบาทมีหน้าที่และความรับผิดชอบ ไม่ใช่แค่ rank ให้โบนัสพลัง ผู้นำอาจถูกท้าทาย/เปลี่ยนเมื่อสูญเสียความไว้วางใจหรือไม่สามารถบริหารงาน

### 6.4 กฎและอัตลักษณ์กิลด์

กิลด์มี charter สั้น ๆ ประกอบด้วย:

- จุดประสงค์หลัก

- งาน/พื้นที่ที่สนใจ

- มาตรฐานรับสมาชิก

- หลักแบ่งรางวัล/ค่าธรรมเนียม

- ความสัมพันธ์กับชุมชน/องค์กรอื่น

- แนวทางจัดการความขัดแย้ง

ค่าเหล่านี้ส่งผลต่อการเลือกสมาชิก งาน และพันธมิตร เช่น กิลด์เน้นสำรวจอาจให้ความสำคัญกับความอยากรู้อยากเห็นและความทนทานต่อความเสี่ยง

### 6.5 เศรษฐกิจกิลด์

- มีบัญชีเงินแยกจากสมาชิก

- รับรายได้จากค่าธรรมเนียม งานบริการ การขายผลผลิต/วัสดุ และงบสาธารณะ

- จ่ายค่าเช่า เครื่องมือ ค่าจ้าง และรางวัลภารกิจจากทุนจริง

- กิลด์ที่งบต่ำต้องลดบริการ เลื่อนงาน หรือขอทุน ไม่สร้างเงินจากศูนย์

- มี ledger ตรวจสอบการเข้าออกของเงิน

- สมาชิกมีความเห็นต่อการใช้ทุน แต่ไม่ต้องมีระบบลงคะแนนเชิงลึกใน MVP

### 6.6 การรับสมาชิกและการแยกตัว

NPC สมัครหรือถูกชวนเข้ากิลด์จาก:

- ทักษะและความเหมาะสม

- ความสัมพันธ์กับสมาชิก

- ความต้องการงาน/การฝึก/การคุ้มครอง

- ชื่อเสียงและเป้าหมาย

- เงื่อนไข charter

NPC อาจปฏิเสธหรือออกจากกิลด์เมื่อความคาดหวังไม่ตรง ค่าตอบแทนไม่เป็นธรรม หรือความไว้ใจต่อผู้นำลดลง

## 7. ฝ่ายอำนาจ (Factions) และกลุ่มผลประโยชน์

### 7.1 ต่างจากกิลด์อย่างไร

- **กิลด์:** องค์กรมีสมาชิก/บริการ/กิจกรรมที่ค่อนข้างชัด เช่น นักผจญภัย ช่างฝีมือ หรือพ่อค้า

- **Faction:** เครือข่ายที่มีผลประโยชน์ มุมมอง อัตลักษณ์ หรือเป้าหมายทางสังคมร่วม อาจไม่มีสำนักงานใหญ่หรือสมาชิกทะเบียนครบ

ตัวอย่าง Faction:

- กลุ่มพ่อค้าที่ต้องการเส้นทางเปิด

- ชุมชนเกษตรกรที่ต้องการคุ้มครองแหล่งน้ำ

- ผู้พิทักษ์ป่าที่ต่อต้านการขุดเหมืองลึก

- ฝ่ายในกิลด์ที่ต้องการเปลี่ยนผู้นำ

- ขุนนาง/ผู้ปกครองท้องถิ่นที่แข่งขันกันเรื่องอำนาจ

### 7.2 คุณสมบัติของ Faction

> Faction
>
> \- purpose / shared_interests
>
> \- members_or_supporters
>
> \- influence_in_regions
>
> \- resources_and_access
>
> \- leadership_or_spokespersons
>
> \- legitimacy / public_support
>
> \- internal_cohesion
>
> \- rivals_and_allies
>
> \- active_goals / grievances
>
> \- history_and_chronicle_links

### 7.3 การเติบโตและการแตกแยก

Faction เติบโตเมื่อเป้าหมายของตนแก้ปัญหาที่คนจำนวนมากสนใจ มีผู้นำที่น่าเชื่อถือ และมีทรัพยากร/เครือข่ายรองรับ ลดบทบาทเมื่อ:

- เป้าหมายสำเร็จหรือไม่มีความเกี่ยวข้อง

- ผู้นำสูญเสียความไว้วางใจ

- ทรัพยากรขาดหรือสมาชิกไม่ได้ประโยชน์

- เกิดความเห็นต่างภายในที่ไม่สามารถประนีประนอม

- คู่แข่งเสนอทางเลือกที่น่าเชื่อถือกว่า

Faction อาจแตกเป็นกลุ่มย่อยหรือเปลี่ยนเป้าหมาย ไม่จำเป็นต้องหายทันที

### 7.4 การต่อรองระหว่างฝ่าย

NPC และองค์กรประเมินความร่วมมือจาก:

- เป้าหมายร่วม

- ความเชื่อถือและประวัติข้อตกลง

- ทรัพยากรที่ต้องแบ่ง

- ความเสี่ยงหากร่วมมือ

- ความเสียหายต่อสมาชิก/ชุมชนของตน

ข้อตกลงมีระยะเวลา เงื่อนไข และผลหากผิดสัญญา ไม่ใช่สถานะ “พันธมิตร” ถาวรที่ไม่มีต้นทุน

## 8. การยกระดับจากชุมชนสู่อาณาจักร

### 8.1 ระดับการเมือง

เสนอให้ใช้ขั้นพัฒนา ไม่กระโดดจากหมู่บ้านเป็นอาณาจักรทันที:

1. **ชุมชน:** ครัวเรือน/ผู้นำท้องถิ่นและกติกาจารีต

2. **เมืองหรือเขตปกครอง:** มีตลาด คลัง หน่วยรักษาความปลอดภัย และการประสานหลายชุมชน

3. **นครรัฐ/สมาพันธ์:** มีหลายเมืองหรือหมู่บ้านร่วมกติกา แบ่งงบและการป้องกัน

4. **อาณาจักร/รัฐรวมศูนย์:** มีผู้ปกครอง/สภา เขตแดน ระบบภาษี/บริการ และความชอบธรรมระดับภูมิภาค

### 8.2 เงื่อนไขการก่อตั้งรัฐ

ต้องผ่านเกณฑ์หลายมิติ ไม่ใช้ประชากรอย่างเดียว:

- **ประชากรและที่อยู่อาศัย:** มีคนและชุมชนที่เชื่อมกันมากพอ

- **ส่วนเกินเศรษฐกิจ:** ผลิตอาหาร/สินค้าเกินการบริโภคพื้นฐานพอเลี้ยงผู้ดูแล/กองรักษาการณ์

- **รายได้ประจำ:** ภาษี ค่าธรรมเนียม หรือรายได้จากการค้าเลี้ยงระบบบริหารได้

- **ความปลอดภัย:** มีความสามารถป้องกันเส้นทาง/ชุมชน ไม่ใช่เพียงครองพื้นที่บนแผนที่

- **การบริหาร:** มีผู้นำ เจ้าหน้าที่ กฎ และระบบส่งข่าว/จัดสรรทรัพยากร

- **ความชอบธรรม:** ชุมชนยอมรับหรืออย่างน้อยไม่ต่อต้านอย่างกว้างขวาง

- **การประสานพื้นที่:** มีเส้นทางและการสื่อสารระหว่างพื้นที่ที่อ้างสิทธิ์

ค่าตั้งต้นที่ใช้ทดสอบอาจต้องมี 3–5 ชุมชนที่เชื่อมต่อกันและผ่านเงื่อนไขด้านรายได้ ความปลอดภัย และความชอบธรรมต่อเนื่องหลายฤดูกาล ก่อนประกาศเป็นรัฐ

### 8.3 ความชอบธรรม (Legitimacy)

ความชอบธรรมไม่เท่ากับกำลังทหารหรือจำนวนสมาชิก แต่เกิดจาก:

- การคุ้มครองและบริการที่ประชาชนได้รับจริง

- ความยุติธรรมของภาษี/กฎ

- ความต่อเนื่องของอาหารและการค้า

- การยอมรับของผู้นำชุมชน

- ประวัติข้อตกลงและการตอบสนองต่อวิกฤต

- วิธีได้มาซึ่งอำนาจ เช่น สืบทอด เลือกตั้ง/สภา หรือยึดครอง

ความชอบธรรมต่ำทำให้เก็บภาษียาก เกิดการต่อต้าน ย้ายถิ่น และองค์กรท้องถิ่นไม่ร่วมมือ

### 8.4 รูปแบบการปกครอง

ไม่จำเป็นต้องทำระบบการเมืองซับซ้อนใน MVP แต่ควรรองรับ archetype:

- **สภาเมือง:** ตัวแทนองค์กร/ชุมชนร่วมตัดสินใจ

- **ผู้ปกครองท้องถิ่น:** ผู้นำคนเดียวมีอำนาจสูงแต่ต้องรักษาความไว้วางใจ

- **สมาพันธ์:** ชุมชนคงอิสระบางส่วนและแบ่งการป้องกัน/การค้า

- **อาณาจักร:** ศูนย์กลางบริหารหลายพื้นที่และเก็บรายได้ตามกฎ

รูปแบบปกครองกำหนดการตอบสนองต่อวิกฤตและการกระจายงบ ไม่ใช่เพียงสกินหรือชื่อ

## 9. การเมือง การสืบทอดอำนาจ และความขัดแย้ง

### 9.1 การสืบทอดผู้นำ

เมื่อผู้นำเสียชีวิต เกษียณ หรือถูกถอดถอน:

1. ระบบเปิดช่วงเปลี่ยนผ่าน

2. ระบุผู้มีสิทธิ์/ความสามารถ/การสนับสนุน

3. ประเมินความชอบธรรมและการยอมรับของกลุ่มหลัก

4. เกิดการเจรจา สภา การแต่งตั้ง หรือการแข่งขันตามรูปแบบการปกครอง

5. ผู้นำใหม่ได้รับอำนาจพร้อมภาระหนี้/ข้อตกลงเดิมที่ยังมีผล

ไม่มีการโอนอำนาจให้ทายาทโดยอัตโนมัติ เว้นแต่รัฐมีธรรมเนียมสืบทอดและยังได้รับการยอมรับ

### 9.2 ความขัดแย้งภายใน

ตัวอย่าง:

- กิลด์แย่งงบ/ตำแหน่งผู้นำ

- ชุมชนไม่ยอมรับภาษีใหม่

- พ่อค้าคัดค้านการปิดเส้นทาง

- ผู้พิทักษ์ป่าขัดแย้งกับกลุ่มเหมือง

ขั้น escalation:

1. ความเห็นต่าง/ข้อร้องเรียน

2. การเจรจาหรือยื่นข้อเสนอ

3. การคว่ำบาตร/หยุดบริการ/ย้ายสมาชิก

4. การแตกองค์กร/ไม่ร่วมมือกับรัฐ

5. วิกฤตการปกครองหรือความขัดแย้งระดับพื้นที่

ไม่กระโดดไปสู่สงครามเต็มรูปแบบจากเหตุการณ์เล็กโดยไม่มีสัญญาณและทางเลือกแก้ไข

### 9.3 ความขัดแย้งระหว่างรัฐ

สำหรับอนาคต อาจใช้การแข่งขันทางการค้า การทูต และการแย่งชิงเส้นทางก่อนสงคราม ระบบสงครามเต็มรูปแบบควรเลื่อนไปหลังแกนสังคม/เศรษฐกิจพิสูจน์แล้ว เพราะเพิ่มภาระ AI และอาจทำลายโลกของผู้เล่นจำนวนมาก

## 10. ความสัมพันธ์ของรัฐกับเศรษฐกิจและประชากร

รัฐมีบทบาททางเศรษฐกิจเฉพาะที่มองเห็นได้:

- เก็บภาษีจากกิจการ/การค้าในขอบเขต

- จ่ายงบหน่วยยาม ถนน สะพาน คลังสำรอง หรือกิลด์สาธารณะ

- กำหนดค่าธรรมเนียม/การอนุญาตตามนโยบาย

- ลงทุนในโครงสร้างพื้นฐานที่เพิ่มกำลังผลิต/ความปลอดภัย

- จัดการหนี้และทุนสำรอง

ทุกการใช้จ่ายต้องมีบัญชีที่มาของเงิน การลดภาษีต้องมีผลต่อรายรับ การเพิ่มภาษีต้องมีผลต่อความชอบธรรม/การค้าหรือบริการ

ผลของการปกครอง

- การรักษาเส้นทางเพิ่มการค้าและลดราคาสินค้าขาดแคลนในระยะยาว

- ภาษีสูงเกินไปทำให้กิจการลดการลงทุนหรือย้ายออก

- นโยบายช่วยเหลือยกระดับความมั่นคง แต่ใช้ทุนสำรอง

- การบริหารดีช่วยลดผลกระทบของภัย แต่ไม่ลบภัยทั้งหมด

- ประชากรเติบโตได้เมื่อมีอาหาร บ้าน งาน และความปลอดภัยรองรับ

## 11. ปฏิสัมพันธ์ของกลุ่มดาวกับองค์กรและอาณาจักร

กลุ่มดาวสามารถชี้นำผ่านข้อมูล พร และเหตุการณ์ตามระบบอิทธิพลเดิม แต่ไม่ควรเป็นผู้ปกครองที่กดปุ่มออกกฎหมายโดยตรง

การชี้นำที่เหมาะสม

- ส่งลางให้ผู้นำรู้ความเสี่ยงของการตัดสินใจ

- ประทานพรต่อการเจรจา/โครงการสาธารณะภายใต้เพดาน

- สนับสนุน NPC ผู้เสนอแนวทางที่ต่างกัน

- ช่วยให้ผู้เล่นอ่านสายสัมพันธ์/ผลกระทบของนโยบายได้ดีขึ้น

ข้อห้าม/ขอบเขต

- ไม่สร้างเงิน ภาษี หรือกองทัพจากศูนย์

- ไม่แต่งตั้งผู้นำโดยตรง

- ไม่ยึดพื้นที่หรือเปลี่ยนกฎรัฐทันที

- ไม่สร้างความสัมพันธ์/การแต่งงานโดยบังคับ

- พลังกลุ่มดาวรวมมีเพดานต่อเหตุการณ์และมีผลลดหลั่นเหมือนเดิม

## 12. การนำเสนอใน UI และพงศาวดาร

### 12.1 แผนที่อำนาจ

เปิดเลเยอร์ “สังคม/อำนาจ” เพื่อแสดง:

- พื้นที่อิทธิพลขององค์กร/รัฐ

- สมาชิกหรือชุมชนที่เชื่อมกัน

- เส้นทางการค้า/การสื่อสาร

- พื้นที่พิพาทหรือความชอบธรรมต่ำ

- สถานะ: กำลังก่อตัว / มั่นคง / ตึงเครียด / แตกแยก

อย่าระบายสีพื้นที่ทับกันเป็นสีเดียวโดยไม่อธิบายว่าเป็นการปกครองร่วม อิทธิพลซ้อน หรือเขตพิพาท

### 12.2 หน้ากิลด์/Faction

แสดงจุดประสงค์ สมาชิกหลัก ผู้นำ งบ สถานะความสัมพันธ์กับองค์กรอื่น ปัญหาภายใน และเหตุการณ์ล่าสุด

### 12.3 หน้ารัฐ/อาณาจักร

แสดงชุมชนในขอบเขต รายรับ–รายจ่าย ความชอบธรรม ความปลอดภัย บริการ และความเห็นของกลุ่มหลัก แสดงแนวโน้มแทนตัวเลขล้นจอ

### 12.4 พงศาวดาร

เหตุการณ์ใหญ่ต้องมีสาเหตุและผล เช่น:

- “กิลด์ผู้คุ้มกันก่อตั้งขึ้น หลังพ่อค้าสามกลุ่มตกลงร่วมทุนลาดตระเวน”

- “สภาอัสเทราขึ้นภาษีเส้นทางเพื่อซ่อมสะพาน การค้าลดลงชั่วคราว แต่ความปลอดภัยเพิ่มขึ้น”

- “สมาพันธ์ลูเมนถือกำเนิดหลังสี่ชุมชนลงนามแบ่งงบคลังสำรอง”

## 13. การจำลองอย่างประหยัดและขยายสเกล

ระดับจำลอง

- ความสัมพันธ์บุคคลที่เกี่ยวกับเหตุการณ์/ตัวละครสำคัญ: รายเส้นแบบละเอียด

- เครือข่ายทั่วไป: เก็บเส้นที่มีความหมายสูงสุดและสรุปส่วนที่เหลือเป็นกลุ่ม

- กิลด์/Faction: จำลองเป็น agent องค์กรที่มีเป้าหมาย งบ และสถานะ

- ชุมชน/รัฐ: จำลองเป็น aggregate indicators พร้อมเหตุการณ์เปลี่ยนผ่าน

- พื้นที่ไกล: ประมวลผลการเจรจา/สมาชิก/เศรษฐกิจแบบรายรอบ ไม่คิดทุกบุคคลทุก tick

การจำกัดกราฟ

- แต่ละ NPC เก็บความสัมพันธ์ละเอียดกับคนที่พบ/ทำงาน/ครอบครัวจำนวนจำกัด เช่น 20–40 รายการ

- ความสัมพันธ์ต่ำและไม่มีปฏิสัมพันธ์นานอาจถูกรวมเป็น “คนรู้จักในชุมชน” แต่เก็บเหตุการณ์สำคัญไว้ใน Chronicle

- เครือข่ายองค์กรเก็บสมาชิกที่มีบทบาทละเอียด ส่วนสมาชิกทั่วไปนับเป็น cohort

- การรวม/แยกองค์กรเกิดจาก threshold และ event ไม่ประเมินทุก tick

ความเสถียรของเซิร์ฟเวอร์

- ใช้ event-driven update เมื่อเกิดการช่วยเหลือ ผิดสัญญา รับสมาชิก หรือเปลี่ยนผู้นำ

- ประเมินความชอบธรรม/ความตึงเครียดเป็นรอบ ไม่ต้องต่อเฟรม

- คำนวณเครือข่ายเฉพาะเพื่อนบ้าน/องค์กรที่ได้รับผลจาก event

- เก็บ event log สำหรับการตรวจสอบ และ snapshot สำหรับโหลดเร็ว

## 14. ขอบเขต MVP

ทำใน MVP

- ความสัมพันธ์หลายมิติและทิศทางระหว่าง NPC สำคัญ

- เครือข่ายครอบครัว/ผู้ดูแล/ครู–ลูกศิษย์

- กิลด์หนึ่งหรือสองประเภทที่เกิดจากความต้องการจริง

- การรับสมาชิก งบกิลด์ การเปลี่ยนผู้นำ และการออกจากองค์กร

- Faction แบบเบื้องต้นที่มีเป้าหมาย/สมาชิก/ความชอบธรรม

- การต่อรอง/ข้อตกลง/ข้อร้องเรียนระดับชุมชน

- พงศาวดารเหตุการณ์สังคมและ UI ดูเครือข่ายแบบเลือก node

เลื่อนไปภายหลัง

- อาณาจักรหลายรัฐที่ทำสงครามเต็มรูปแบบ

- ภาษีและกฎหมายแบบแก้ไขได้หลายร้อยนโยบาย

- เลือกตั้ง/รัฐประหาร/ราชวงศ์ซับซ้อน

- การแสดง social graph ทั้งโลกพร้อมกัน

- ระบบการเมืองระหว่างผู้เล่นกลุ่มดาวโดยตรง

## 15. ตัวอย่างการเติบโตจากความสัมพันธ์สู่รัฐ

1. นักผจญภัยสามคนช่วยคุ้มกันพ่อค้าบนเส้นทางเดียวกันหลายครั้ง เกิดความไว้ใจและความเชี่ยวชาญร่วม

2. พ่อค้าสองรายตกลงสมทบค่าซ่อมสะพาน เพราะการเดินทางปลอดภัยขึ้นจะช่วยธุรกิจของตน

3. ช่างฝีมือกับยามเข้าร่วมกลุ่มไม่เป็นทางการเพื่อรักษาเส้นทาง

4. กลุ่มนี้ตั้งสมาคมคุ้มกัน มีคลังเล็ก ค่าธรรมเนียม และหัวหน้าที่สมาชิกยอมรับ

5. หมู่บ้านใกล้เคียงเริ่มพึ่งพาบริการของสมาคม แต่เกิดข้อร้องเรียนเรื่องค่าผ่านทาง

6. ผู้นำสมาคมเจรจากับสภาเมือง สร้างข้อตกลงคุ้มกันโดยได้รับงบสาธารณะและเปิดบัญชี

7. เมื่อหลายชุมชนร่วมแบ่งงบ ความปลอดภัย และการจัดการเส้นทางอย่างต่อเนื่อง จึงก่อตั้งสมาพันธ์

8. สมาพันธ์จะพัฒนาเป็นรัฐรวมศูนย์ได้ก็ต่อเมื่อมีรายรับ การบริหาร ความปลอดภัย และความชอบธรรมเพียงพอ ไม่ใช่เพียงควบคุมพื้นที่บนแผนที่

แต่ละขั้นมีทางแยกและความเสี่ยง เช่น สมาคมแตกจากข้อพิพาทเรื่องค่าธรรมเนียม หรือชุมชนเลือกคงอิสระ

## 16. คำถามทดสอบระบบ

1. ผู้เล่นเข้าใจได้หรือไม่ว่าเหตุใด NPC จึงไว้วางใจ/ไม่ไว้วางใจองค์กรหนึ่ง?

2. กิลด์มีพฤติกรรมต่างจากแค่ชื่อกลุ่มและแถบสมาชิกหรือไม่?

3. การแต่งงาน/ครัวเรือนเกิดจากแรงจูงใจของ NPC และยังมีทางเลือกหลากหลายหรือไม่?

4. ผู้สืบทอดได้ประโยชน์จากเครือข่าย แต่ยังต้องสร้างความชอบธรรมของตนหรือไม่?

5. การก่อตั้งรัฐแก้ปัญหาบางอย่างแต่สร้างภาระใหม่หรือไม่?

6. การเปลี่ยนผู้นำทำให้ชุมชนตอบสนองอย่างอ่านเข้าใจได้หรือไม่?

7. ระบบจำลองเครือข่ายขนาดใหญ่โดยไม่ต้องประเมินทุกเส้นความสัมพันธ์ทุก tick ได้หรือไม่?

8. ผู้เล่นมองเห็นสาเหตุและผลของการเปลี่ยนแปลงระดับสังคมในพงศาวดารหรือไม่?

## 17. ลำดับการพัฒนา

1. ทำ edge ความสัมพันธ์หลายมิติและ event ที่ปรับค่า

2. เชื่อมความสัมพันธ์กับ Utility AI และการเลือกเพื่อน/ปาร์ตี้

3. เพิ่มครัวเรือน คู่ชีวิต และการสืบทอดแบบสมัครใจ

4. เพิ่มกิลด์ที่มีสมาชิก งบ และเป้าหมายจริง

5. เพิ่ม Faction และความขัดแย้งระดับชุมชน

6. เพิ่มขั้นเมือง/สมาพันธ์/รัฐ เมื่อระบบเศรษฐกิจและประชากรเสถียร

7. เพิ่มแผนที่อำนาจ UI และ Chronicle ข้ามองค์กร/ยุค

**หลักจัดลำดับ:** อย่าเริ่มจากทำแผนที่อาณาจักรหรือระบบสงครามก่อนพิสูจน์ว่า NPC สร้างความสัมพันธ์ องค์กร และผลประโยชน์ร่วมได้อย่างน่าเชื่อถือ
