ดนตรีและเสียงที่เปลี่ยนไปตามยุค ความเจริญ และความทรงจำของโลก

**เกม:** พงศาวดารใต้ดวงดาว  
**บริบท:** โลกออนไลน์ร่วมกันที่ NPC และอารยธรรมเปลี่ยนแปลงตามเวลา  
**เวอร์ชัน:** 0.1 — ข้อเสนอสำหรับต้นแบบ  
**เป้าหมาย:** ให้ผู้เล่น “ได้ยิน” การเปลี่ยนแปลงของสังคมและประวัติศาสตร์ โดยไม่ทำให้เพลงเปลี่ยนฉับพลันหรือใช้ทรัพยากรเกินจำเป็น

**หลักการ:** เสียงดนตรีไม่ควรบอกแค่ว่าเมืองนี้มีเทคโนโลยีระดับไหน แต่ควรสะท้อนด้วยว่าเมืองนี้มีชีวิตชีวา ปลอดภัย เชื่อใจกัน หรือกำลังเผชิญความสูญเสียเพียงใด

## 1. ประสบการณ์เป้าหมาย

ผู้เล่นควรรับรู้ความเปลี่ยนแปลงได้โดยไม่ต้องอ่าน UI ตลอดเวลา เช่น:

- หมู่บ้านเล็กให้ความรู้สึกใกล้ชิดธรรมชาติและกิจวัตรประจำวัน

- เมืองการค้าที่เติบโตมีจังหวะ เสียงผู้คน และสีสันทางดนตรีเพิ่มขึ้น

- อารยธรรมรุ่งเรืองมีความเต็มอิ่ม แต่ไม่จำเป็นต้องดังหรือยิ่งใหญ่เสมอไป

- เมืองที่ขาดแคลนหรือแตกแยกอาจมีเสียงกิจกรรมลดลง จังหวะไม่มั่นคง หรือเหลือทำนองบางส่วน

- ยุคใหม่เพิ่มเครื่องดนตรี/การเรียบเรียงอย่างค่อยเป็นค่อยไป ขณะยังจดจำธีมเดิมของอารยธรรม

- เหตุการณ์สำคัญและคนรุ่นก่อนทิ้ง “ร่องรอยทางเสียง” ที่กลับมาในเพลงของคนรุ่นหลัง

## 2. แกนออกแบบเสียง

### 2.1 แยก “ยุค” ออกจาก “สภาพสังคม”

ยุคกำหนดคลังเสียง/เครื่องดนตรี/รูปแบบการเรียบเรียงที่มีอยู่ ส่วนสภาพสังคมกำหนดอารมณ์และความหนาแน่นของเสียง เช่น เมืองยุคเก่าที่รุ่งเรืองอาจฟังมีชีวิตชีวากว่าเมืองยุคใหม่ที่อยู่ในภาวะอดอยาก

### 2.2 ใช้ธีมร่วมที่วิวัฒน์ ไม่เปลี่ยนเพลงทิ้งทั้งหมด

อารยธรรม/ภูมิภาคมี motif หลักหนึ่งหรือหลายชุด เมื่อสังคมเติบโตให้เปลี่ยนเครื่องดนตรี ฮาร์โมนี จังหวะ หรือวิธีบรรเลง motif เดิม เพื่อให้ผู้เล่นรู้สึกว่า “นี่คือบ้านเดิมที่เปลี่ยนไป”

### 2.3 ให้เสียงเป็นสัญญาณ ไม่ใช่บทลงโทษ

ความตึงเครียดทางเสียงเตือนสถานการณ์ได้ แต่ต้องไม่ดังต่อเนื่องหรือบังคับให้ผู้เล่นอยู่ในอารมณ์เครียดตลอดเวลา ผู้เล่นควบคุมระดับเพลง เสียงเหตุการณ์ และความเข้มได้

### 2.4 ทำงานแบบ event-driven

อัปเดตสถานะเสียงเมื่อเกิดการเปลี่ยนแปลงสำคัญ เช่น ฤดูกาล/ความเจริญ/ภัยพิบัติ ไม่คำนวณ music state ใหม่ทุก frame หรือทุก NPC

## 3. ตัวแปรสถานะเสียงของโลก

ระบบเสียงรับค่าจากสถานะโลกที่ผ่านการสรุปแล้ว ไม่อ่าน AI decision ดิบของ NPC ทุกตัว

> AudioWorldState
>
> \- culture_id / region_id
>
> \- era_stage // ระยะอารยธรรม
>
> \- prosperity // ความมั่งคั่ง/กิจกรรมทางเศรษฐกิจ
>
> \- cohesion // ความเป็นปึกแผ่น/ความไว้ใจ
>
> \- safety // ความปลอดภัย
>
> \- population_activity // ความหนาแน่นกิจกรรมคน
>
> \- nature_health // สภาพแวดล้อม
>
> \- threat_level // ภัยเฉพาะหน้า
>
> \- time_of_day / season
>
> \- active_global_event
>
> \- landmark_state // ตลาด สะพาน หอคอย ฯลฯ
>
> \- chronicle_motifs\[\] // motif เหตุการณ์/บุคคลที่ได้รับอนุญาตให้แสดง

ตัวแปรต่อเนื่อง normalize เป็น 0–1 ส่วน era/culture/event เป็น discrete state

ค่าที่ไม่ควรผูกเข้ากับเพลงโดยตรง

- จำนวนผู้เล่นออนไลน์แบบดิบ

- ปริมาณการใช้เงินจริง/แต้มอิทธิพลของกลุ่มดาว

- ตัวตนหรือข้อความส่วนตัวของผู้เล่น

- การตัดสินใจ AI ที่ยังไม่ commit เป็นเหตุการณ์ในโลก

เพลงควรสะท้อนผลที่เกิดในโลก ไม่ใช่พยายามเดาว่าผู้เล่นกำลังจะทำอะไร

## 4. โครงสร้างดนตรีแบบ Adaptive Layers

### 4.1 ชั้นดนตรี

ใช้ stems/เลเยอร์ที่สามารถผสมกันได้ เช่น:

1.  **Foundation:** drone, ambient harmony, ธีมหลักของภูมิภาค

2.  **Pulse:** จังหวะเบา/พื้นผิวเสียงที่สะท้อนกิจกรรม

3.  **Melody:** motif หลักหรือทำนองตัวละคร/ชุมชน

4.  **Color:** เครื่องดนตรี/texture ที่บ่งบอกวัฒนธรรมและยุค

5.  **Tension:** ostinato, dissonance, pulse เร่ง เมื่อมีภัย

6.  **Resolution:** cadence/phrase สำหรับการคลี่คลายหรือกลับสู่ภาวะปกติ

### 4.2 กฎผสมเลเยอร์

- เลเยอร์พื้นฐานหนึ่งชุดทำงานในพื้นที่สำคัญ

- เพิ่มความหนาแน่นตาม prosperity/population activity ไม่ใช่ตามจำนวน NPC รายตัว

- Tension layer ทำงานจาก threat/event ที่ผ่าน threshold และมี hysteresis

- ยุคใหม่เพิ่มสีสัน/การเรียบเรียง โดยยังคง motif หรือช่วงเสียงเดิมบางส่วน

- จำกัดจำนวนเลเยอร์ที่เล่นพร้อมกัน เช่น ไม่เกิน 4–5 stems ในโซนทั่วไป

- เลเยอร์ที่ไม่จำเป็นให้หยุด/พัก ไม่เล่นเงียบต่อเนื่องโดยไม่เกิดประโยชน์

### 4.3 การเปลี่ยนสถานะอย่างนุ่มนวล

- เปลี่ยนเลเยอร์บนจังหวะห้อง/จุดเปลี่ยนวลีเมื่อทำได้

- crossfade ปกติประมาณ 2–6 วินาที

- การเปลี่ยนยุคมี transition cue สั้นเฉพาะครั้ง แล้วค่อยเปิด arrangement ใหม่

- อย่า restart เพลงทั้งเพลงทุกครั้งที่ผู้เล่นข้ามขอบเขตเมือง

- ใช้ transition cooldown/hysteresis ป้องกัน state สั่นไปมาจากค่าที่แกว่งใกล้ threshold

ตัวอย่าง hysteresis: เปิด tension เมื่อ threat \> 0.65 ต่อเนื่อง 10 วินาที แต่ปิดเมื่อ threat \< 0.45 ต่อเนื่อง 20 วินาที

## 5. เสียงของยุคและความเจริญ

ระยะด้านล่างเป็นอัตลักษณ์ทางเสียง ไม่ใช่การจัดอันดับคุณค่าของวัฒนธรรม

| ระยะอารยธรรม             | ลักษณะดนตรี                                              | Soundscape                                   |
|--------------------------|--------------------------------------------------------|----------------------------------------------|
| **ชายขอบ/ชุมชนตั้งต้น**      | ทำนองโปร่ง เครื่องสายเดี่ยว/ลมพื้นบ้าน เสียงธรรมชาติมีพื้นที่         | เตาไฟ งานครัว เสียงสัตว์ งานซ่อมพื้นฐาน             |
| **หมู่บ้าน/เครือข่ายช่าง**     | จังหวะสม่ำเสมอขึ้น มีเครื่องเคาะและการตอบรับระหว่างทำนอง        | โรงตีเหล็ก ตลาดเล็ก เสียงคนเรียกซื้อขาย             |
| **เมืองการค้า/กิลด์**        | มี bass line/ชั้นฮาร์โมนีเพิ่ม motif หลายกลุ่มสนทนากัน           | ตลาดหนาแน่น ล้อเกวียน ท่าเรือ/คลังสินค้า             |
| **นครรัฐ/สถาบันมั่นคง**      | เรียบเรียงหลายแนว มีธีมสาธารณะหรือ motif ของสภา/กิลด์         | หอนาฬิกา พิธีการ ยามลาดตระเวนและพื้นที่สาธารณะ      |
| **อาณาจักร/เครือข่ายภูมิภาค** | ธีมใหญ่ขึ้นแต่ยังมี motif ท้องถิ่นหลายแบบร่วมกัน                   | เสียงเมืองหลวงและความแตกต่างของพื้นที่รอบนอก        |
| **ยุคเปลี่ยนผ่าน/เสื่อมถอย**   | นำ motif เก่ากลับมาแบบลดทอน เปลี่ยนจังหวะ/ฮาร์โมนีตามสถานการณ์ | กิจกรรมหายไปบางจุด อาคารทรุด เสียงบริการที่หยุดทำงาน |

ข้อสำคัญ

- ยุคใหม่ไม่จำเป็นต้อง “อลังการกว่า” ทุกครั้ง

- เมืองรุ่งเรืองแต่มีความเหลื่อมล้ำอาจมีดนตรีศูนย์กลางและเขตรอบนอกที่ต่างกัน

- วัฒนธรรมใช้สีสันของตนเอง ไม่ใช้เครื่องดนตรีชนิดเดียวแทนทุกอารยธรรม

- ความเสื่อมถอยไม่ควรทำให้ทุกเสียงกลายเป็น minor/dissonance แบบสูตรสำเร็จ

## 6. โมเดลวิวัฒนาการทางดนตรีของอารยธรรม

### 6.1 Cultural Motif Seed

แต่ละวัฒนธรรม/ภูมิภาคมีชุดข้อมูลต้นทาง เช่น:

- tonal center/interval palette

- จังหวะพื้นฐาน

- contour ทำนอง

- เครื่องดนตรี/วัสดุเสียงที่มีในภูมิภาค

- ลักษณะการประสานเสียง

- motif สำหรับพิธี ตลาด การเดินทาง หรือการไว้ทุกข์

สร้างโดยนักแต่งเพลง/ทีมเสียงเป็นชุดที่ดูแลได้ ไม่จำเป็นต้องแต่งเพลงอิสระแบบสุ่มทุกครั้ง

### 6.2 การสืบทอดระหว่างยุค

เมื่ออารยธรรมเปลี่ยน stage:

- เก็บ motif หลักไว้บางส่วน

- เปลี่ยน orchestration ตามเครื่องดนตรี/ช่าง/ทรัพยากรที่มี

- เพิ่ม motif ใหม่จากเหตุการณ์สำคัญ เช่น การสร้างสะพานหรือชนะวิกฤต

- หากมีการอพยพ/รวมอาณาจักร ให้เกิดการผสม motif ตามการติดต่อจริง

- หากชุมชนแตกแยก อาจมี motif รุ่นเก่าที่คงอยู่ในพื้นที่เดิม

### 6.3 ไม่ผูกเพลงกับเทคโนโลยีอย่างเดียว

ความเปลี่ยนแปลงของ arrangement ใช้เงื่อนไขร่วม:

> era_audio_shift = era_progress
>
> \+ craft_and_instrument_availability
>
> \+ cultural_exchange
>
> \+ institutional_activity
>
> \+ community_cohesion

จึงไม่ปลดล็อกเครื่องดนตรีใหม่เพียงเพราะตัวเลข “ยุค” ขึ้น ถ้าโลกยังไม่มีช่าง วัสดุ หรือการแลกเปลี่ยนที่รองรับ

## 7. ความเปลี่ยนแปลงตาม prosperity/cohesion/safety

### 7.1 ความรุ่งเรือง

- เพิ่มชั้นจังหวะ/กิจกรรมและความหลากหลายของ soundscape

- เปิด motif งานเทศกาล/ตลาด เมื่อมีงบและกิจกรรมจริง

- ไม่เพิ่มความดังรวมโดยอัตโนมัติ

### 7.2 ความเป็นปึกแผ่น

- ใช้ทำนองตอบรับ/ประสานกันมากขึ้นเมื่อชุมชนร่วมมือ

- หากมี faction conflict ให้ใช้ motif ที่ไม่ลงรอยหรือจังหวะไม่พร้อมกันอย่างละเอียด ไม่ทำเป็นเสียง “ชั่วร้าย” แทนฝ่ายใด

### 7.3 ความปลอดภัย

- เมืองปลอดภัยมี ambience เปิดโล่งและเสียงกิจวัตรกลับมา

- ความเสี่ยงสูงเพิ่ม tension layer เฉพาะเมื่อผู้เล่นอยู่ในพื้นที่/เหตุการณ์ที่เกี่ยวข้อง

- เมื่อภัยผ่านพ้น ใช้ resolution cue แล้วค่อยถอน tension ไม่ค้างเพลงต่อสู้ทั้งเมือง

### 7.4 ความขาดแคลน/เสื่อมถอย

- ลดเสียงกิจกรรมที่ไม่มีอีกต่อไป เช่น ตลาด/โรงงานที่ปิดจริง

- คงเสียงพื้นฐานของผู้คน/ธรรมชาติ เพื่อไม่ให้พื้นที่ฟังเป็นสุญญากาศ

- ใช้ motif เดิมในรูปแบบบางลง แสดงความทรงจำ ไม่ใช้เอฟเฟกต์เศร้าแบบบังคับ

## 8. Soundscape ที่ขับเคลื่อนโดย NPC

เสียงพื้นที่ไม่ควรทำเสียงเฉพาะ NPC ทุกคนตลอดเวลา ให้สรุปเป็น “activity field” ตามโซน:

- จำนวนงานที่กำลังดำเนิน: ตลาด/ฟาร์ม/ช่าง/การขนส่ง

- ความหนาแน่นคนโดยช่วงเวลา

- สถานะบริการ เช่น ตลาดเปิด/ปิด กิลด์รับงานหรือหยุดกิจการ

- สภาพแวดล้อม เช่น ฝน ลม น้ำ สัตว์

- สถานะวิกฤต/ความปลอดภัย

ตัวอย่างเสียงตามกิจกรรม

- ตลาดคึกคักขึ้นเมื่อจำนวนร้านเปิดและการซื้อขายจริงเพิ่ม

- เสียงโรงตีเหล็กเกิดเมื่อมีงานผลิต ไม่ loop เต็มกำลังทั้งวัน

- หากเส้นทางขาด เสียงเกวียน/เรือขนส่งลดลงและมีประกาศ/ข่าวแทน

- เทศกาลเกิดเมื่อชุมชนมีทรัพยากรและเหตุผลจัดจริง ไม่สุ่มเล่นซ้ำทุกคืน

- หากกิลด์ล้มละลาย เสียงกิจกรรมในอาคารค่อย ๆ ลดและอาจกลายเป็นพื้นที่เงียบ/ใช้ประโยชน์แบบใหม่

| Phase      | แนวทางเสียง                                                  |
|------------|-------------------------------------------------------------|
| ข่าวเตือน    | เพิ่ม motif/สัญญาณที่ไม่รบกวน เช่น ระฆัง/ลมเปลี่ยน โดยไม่เล่น alarm ซ้ำถี่ |
| ผลกระทบเริ่ม | เพิ่ม texture/เครื่องหมายเสียงเฉพาะพื้นที่                           |
| วิกฤต       | เปิด tension layer ในพื้นที่เกี่ยวข้อง เพิ่มความหนาแน่นตามความเร่งด่วน   |
| คลี่คลาย     | เล่น resolution cue ตามผลจริง ไม่เหมารวมว่าทุกผลคือชัยชนะ          |
| ฟื้นฟู        | ลด tension และเพิ่ม motif งานซ่อม/การกลับมาของกิจกรรมเมื่อสถานะดีขึ้น |

เสียงเตือนซ้ำมี cooldown ต่อผู้เล่น/พื้นที่ และมีตัวเลือกปิด/ลดระดับเสียงเตือน

## 10. Motif ของตัวละครและความทรงจำ

### 10.1 Character motif

NPC สำคัญ/ปาร์ตี้อาจมี motif สั้น ๆ ที่ผูกกับบุคลิกหรือประวัติ ไม่ต้องเล่นทุกครั้งที่ปรากฏ

เงื่อนไขเรียกใช้:

- จุดเปลี่ยนใน Character Arc

- การกลับมาพบคนสำคัญ

- การสืบทอดบทบาท/ความรู้

- การเสียชีวิตหรือการรำลึก ตามบริบทและความเหมาะสม

### 10.2 การแปร motif

- motif เดิมกลับมาโดยใช้เครื่องดนตรี/ฮาร์โมนีของยุคใหม่

- ลูกศิษย์/ทายาทอาจได้รับ fragment ของ motif ไม่จำเป็นต้องเหมือนต้นฉบับ

- การสืบทอด motif เป็นสัญญาณเรื่องราว ไม่ใช่หลักฐานว่าตัวละครใหม่มีบุคลิกเหมือนผู้ตาย

### 10.3 ความเป็นส่วนตัว/ความรู้

อย่าเล่น motif ที่เผยความลับของ NPC ให้ผู้เล่นก่อนข้อมูลนั้นเปิดเผยตามกติกา หากเรื่องยังเป็น private/local ให้เสียงแสดงเฉพาะในบริบทที่ผู้เล่นมีสิทธิ์รับรู้

## 11. การเปลี่ยนเสียงตามพื้นที่ เวลา และมุมมองผู้เล่น

- มิกซ์พื้นที่ควร blend ระหว่างเขตอย่างช้า ๆ ไม่ตัด ambience ทันทีที่ข้ามพรมแดน

- เสียงกลางคืนเปลี่ยนกิจกรรม/สัตว์/ระดับผู้คนตามระบบกิจวัตร NPC

- ฤดูกาลปรับ ambience และ instrument layer ตามธรรมชาติและเศรษฐกิจพื้นที่

- เสียงผู้เล่นเฉพาะบุคคล เช่น volume, reverb และ accessibility เป็น client-side

- เพลงของโลกใช้ world state เดียวกัน แต่ความดัง/เลเยอร์ที่ผู้เล่นได้ยินปรับเฉพาะเครื่องได้

- ไม่ส่ง audio stems ทั้งหมดผ่านเครือข่าย; ส่งเพียง state/event ID ที่จำเป็น

## 12. สถาปัตยกรรม Implementation

### 12.1 Audio State Aggregator

รับการเปลี่ยนแปลงจากระบบโลกและอัปเดต state แบบ batch/event-driven เช่น เมื่อ:

- ขึ้นฤดูกาล/ยุค

- prosperity/cohesion/safety ข้าม threshold

- Global Event เปลี่ยน phase

- สถานที่สำคัญสร้าง/ปิด/ฟื้นฟู

- Chronicle arc ถึงหมุดที่อนุญาตให้มี motif

### 12.2 Audio Parameter Mapper

แปลง state เป็นพารามิเตอร์ เช่น:

> Prosperity 0–1 → density of rhythm / activity layers
>
> Cohesion 0–1 → degree of harmonic alignment
>
> Safety 0–1 → tension layer intensity (inverse relationship)
>
> Era stage → available orchestration palette
>
> Population activity → ambience crowd density
>
> Threat level → localized tension and alert cue
>
> Season/time → environment and arrangement variation

ใช้ smoothing/interpolation เพื่อไม่ให้ค่าเสียงกระโดดตามการเปลี่ยนตัวเลขเล็กน้อย

### 12.3 Audio Event Queue

- ใช้ event_id ป้องกันเสียงซ้ำเมื่อ reconnect หรือ state replay

- จัดลำดับ event สำคัญ เช่น raid phase \> local flourish \> routine ambience

- เสียงที่หมดความหมายเมื่อช้าเกินไปให้ทิ้ง ไม่เล่นย้อนหลังรวดเดียว

- ห้าม event เสียงที่ไม่เกี่ยวข้องแย่งช่องจาก alert สำคัญ

### 12.4 Middleware-agnostic

สามารถทำด้วยระบบ audio middleware/engine ใดก็ได้ หลักที่ต้องรักษาคือ state parameters, snapshots, crossfades, voice limiting และ event idempotency ไม่ผูกดีไซน์กับเครื่องมือเฉพาะ

## 13. งบประมาณเสียงและประสิทธิภาพ

ค่าตั้งต้นสำหรับการวางแผน ต้องปรับตามแพลตฟอร์มจริง:

- เพลงพื้นที่ทั่วไปเล่นพร้อมกันไม่เกิน 4–5 stems

- ช่วง transition อาจซ้อน stem เก่า/ใหม่ชั่วคราว แต่กำหนด voice limit

- ambient loop ใช้จำนวนเสียงจำกัดและระยะ audible ตามความสำคัญ

- NPC ทั่วไปไม่สร้างเสียงเฉพาะตัวเมื่ออยู่นอกระยะ/ไม่เกี่ยวข้อง

- แบ่ง LOD: ใกล้ผู้เล่นมีรายละเอียดเสียงสูง; ไกลใช้ bed/aggregate ambience

- stream เพลงและ sound bank ตามโซน; unload bank ที่ไม่ใช้

- ตั้งเป้าขนาด memory budget ตามแพลตฟอร์มเป้าหมายหลังทำ vertical slice; ห้ามเพิ่มรายละเอียดจนไม่เหลือ headroom สำหรับ SFX/voice

- ใช้ profiler ดู active voices, streaming stalls, memory, CPU และ clipping ในฉากคนหนาแน่น

นโยบายเมื่อเครื่องช้า

ลด ambience รายละเอียด/จำนวน stem ก่อนปิด audio cue สำคัญ เช่น คำเตือนภัยหรือเสียงระบุตำแหน่ง

## 14. UX และ Accessibility

มีการตั้งค่าแยก:

- Master volume

- Music volume

- Ambient/world volume

- Alert/event volume

- UI/notification sound volume

- Dynamic intensity: เต็ม / ลด / คงที่ / ปิด adaptive layer

- ลดเสียงฉับพลัน/ลด dynamic range

- ปิดเสียงเตือนซ้ำแต่คงสัญลักษณ์ภาพ

- mono output / subtitle หรือ visual cue สำหรับเสียงสำคัญ

- ปรับความถี่เสียงแหลม/เสียงเบสตามความสบาย

ผู้เล่นเลือกโหมด “สงบ” ที่ลด tension ได้ แต่ UI ยังคงแสดงภัยอย่างเท่าเทียม ไม่ทำให้เสียข้อมูลเกม

## 15. การสร้างและส่งมอบคอนเทนต์เสียง

แต่ละ cue/stem ควรมี metadata:

> AudioAsset
>
> \- asset_id, culture_id, era_range, region_tags
>
> \- mood_tags, event_tags, instrument_tags
>
> \- loop_length, bpm_or_free_time, key_or_tonal_center
>
> \- compatible_stems\[\], transition_points\[\]
>
> \- loudness_target, priority, voice_cost
>
> \- variation_seed_rule, accessibility_notes

แนวทางทีมเสียง

1.  แต่ง motif วัฒนธรรมหลักให้จำได้ในรูปแบบเรียบง่าย

2.  ทำเวอร์ชันหลาย arrangement ตาม stage ไม่ใช่หลายเพลงที่ไม่เกี่ยวกัน

3.  ผลิต stems ที่มีจุดต่อและ cadence เข้ากัน

4. ทำ variation มากกว่าการสุ่ม pitch/จังหวะจนเสียเอกลักษณ์

5. ตรวจการ loop ระยะยาว/ซ้ำถี่ และทดสอบกับ gameplay จริง

6. ทำ cue สำหรับภัยพิบัติและ recovery ทั้งผลดี/ผลเสียหลายระดับ

7. บันทึกสิทธิ์การใช้และ provenance ของ asset ให้ชัดเจน

## 16. ตัวอย่างสถานการณ์เสียง

หมู่บ้านลูเมนก่อนและหลังเติบโต

**ก่อน:** motif เครื่องลม/เครื่องสายเดี่ยว มีเสียงลำธารและกิจวัตรเบา ๆ ตลาดมีเสียงเป็นช่วง

**หลังมีสะพานและกิลด์:** motif เดิมถูกเล่นด้วยเครื่องดนตรีเพิ่ม มีจังหวะการเดินทางและเสียงการค้า แต่ไม่เปลี่ยนทำนองหลักทิ้ง

**หลังภัยแล้ง:** เลเยอร์ตลาด/ฟาร์มลดลง เสียงน้ำบางลง มี tension เบาเฉพาะพื้นที่ แต่ motif หลักยังอยู่

**หลังชุมชนสร้างระบบชลประทานและฟื้นตัว:** เพิ่มจังหวะกิจกรรมและ motif งานร่วมกัน เสียงไม่กลับเต็มทันที แต่ฟื้นตามผลผลิตและความมั่นคงจริง

**รุ่นถัดไป:** เพลงเด็ก/พิธีชุมชนใช้ fragment ของ motif เก่าที่เคยเล่นในช่วงภัยแล้ง เป็นความทรงจำร่วม ไม่ใช่การเล่นแฟลชแบ็กโดยไม่มีเหตุ

## 17. เกณฑ์ทดสอบ

1. ผู้เล่นแยกความรู้สึกของพื้นที่ตั้งต้น เมืองรุ่งเรือง และเมืองวิกฤตได้ แม้ไม่เห็น UI

2. การเปลี่ยนยุคฟังเป็นวิวัฒนาการของวัฒนธรรมเดิม ไม่ใช่เพลงใหม่ที่ตัดขาดทุกครั้ง

3. ค่าความเจริญแกว่งเล็กน้อยไม่ทำให้ layer เปิดปิดถี่

4. ผู้เล่นเข้าใจ/ปิดเสียงเตือนซ้ำได้โดยไม่พลาดข้อมูลผ่าน UI

5. เมื่อ event จบ tension layer ถอนตามผลจริงโดยไม่ค้าง

6. motif ที่อ้างถึงความลับไม่ดังให้ผู้เล่นที่ยังไม่มีสิทธิ์รับรู้

7. จำนวนเสียง/หน่วยความจำไม่เพิ่มตามจำนวน NPC โดยตรง

8. การ reconnect ไม่เล่น cue เก่าย้อนซ้ำจำนวนมาก

9. มิกซ์ยังอ่านออกในฉากมี SFX/เสียงตลาด/เสียงต่อสู้พร้อมกัน

10. ผู้เล่นที่ใช้โหมดลด dynamic intensity ยังได้รับข้อมูลเหตุการณ์ครบ

## 18. ลำดับการพัฒนา

MVP

1. สร้าง motif ประจำวัฒนธรรม/ภูมิภาคหนึ่งชุด

2. ทำ 3 arrangement stage: ชุมชนตั้งต้น / เมืองรุ่งเรือง / วิกฤต–ฟื้นฟู

3. เชื่อม AudioWorldState: prosperity, safety, threat, time/season

4. ทำ adaptive layers 2–4 ชั้นและ transition ที่ไม่ตัดเพลงฉับพลัน

5. ทำ soundscape ของตลาด/งานช่างจาก activity aggregate

6. เพิ่มตัวเลือก accessibility และ profiler

หลังพิสูจน์ระบบ

- เพิ่มหลายวัฒนธรรม/การแลกเปลี่ยน motif

- เพิ่ม motif ของตัวละคร/กิลด์/อาณาจักร

- เชื่อม Chronicle และ Legacy เข้ากับเพลง

- เพิ่มสถานะการปกครอง/ความเป็นปึกแผ่น

- เพิ่มการปรับเสียงตามผู้เล่นแบบ personalized โดยไม่เปลี่ยนข้อเท็จจริงโลก

## 19. ข้อสรุป

Dynamic Audio ควรทำให้ประวัติศาสตร์ “ได้ยินได้” ผ่านสามชั้นที่ทำงานร่วมกัน:

1. **อัตลักษณ์:** motif/สีสันของวัฒนธรรมและภูมิภาค

2. **สภาพปัจจุบัน:** ความรุ่งเรือง ความปลอดภัย ความสามัคคี และภัย

3. **ความทรงจำ:** motif ที่แปรไปตามเหตุการณ์สำคัญและการสืบทอด

เริ่มจากระบบ state-driven ที่ใช้ stems และ event cues ที่ทีมควบคุมได้ก่อน แล้วค่อยเพิ่มความหลากหลายเมื่อ core simulation เสถียร การเปลี่ยนเสียงต้องมีเหตุผล นุ่มนวล และใช้ทรัพยากรตามความสำคัญ ไม่ใช่เล่นเสียงเฉพาะตัวให้ทุก NPC ตลอดเวลา

**คำถามพิสูจน์ระบบ:** เมื่อผู้เล่นกลับมายังเมืองเดิมหลังเวลาผ่านไป เขาได้ยินทั้งความทรงจำของเมืองและสิ่งที่เปลี่ยนไป โดยไม่ต้องเปิดหน้าสถานะเพื่อเข้าใจหรือไม่?
