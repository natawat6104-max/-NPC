## 1. หลัก UX ที่ใช้กับทุกหน้าจอ

### 1.1 โลกออนไลน์ไม่ถูกหยุดด้วยผู้เล่นคนเดียว

> **อัปเดต (D2):** ใน MVP แบบเล่นคนเดียว ผู้เล่นหยุด/เร่งเวลาโลกได้ ข้อนี้ใช้เฉพาะระยะออนไลน์

ปุ่มหยุดเวลาระดับโลกไม่มีในเกมออนไลน์ร่วมกัน ผู้เล่นสามารถหยุด **การเล่นภาพย้อนหลัง/แอนิเมชันบนเครื่องตนเอง** หรือเปิดแผงตรวจสอบได้ แต่โลกและ NPC ยังคงเดินต่อบนเซิร์ฟเวอร์

แยกสถานะให้ชัด:

- **หยุดดู:** หยุดกล้อง/แอนิเมชันเฉพาะเครื่อง ไม่หยุดโลก

- **เหตุการณ์กำลังเกิด:** สถานะปัจจุบันอัปเดตตามเซิร์ฟเวอร์

- **ข้อมูล ณ เวลา:** ระบุว่าแผนที่/ข้อมูลล่าสุดอัปเดตเมื่อใด หากมี latency

### 1.2 ข้อมูลก่อนการกระทำ

ก่อนใช้พลังทุกครั้ง ต้องเห็นค่าใช้จ่าย ผลที่คาด ข้อจำกัด คูลดาวน์ และสถานะการสนับสนุนจากกลุ่มดาวอื่น การยืนยันต้องเป็นการกระทำที่ชัดเจน ไม่เปิดใช้อำนาจจากการคลิกเป้าหมายโดยไม่ตั้งใจ

### 1.3 ใช้สรุปก่อน แล้วค่อยเปิดรายละเอียด

หน้าหลักแสดงข้อมูลระดับ “รู้ว่ามีอะไรเกิดขึ้น” ส่วนรายละเอียดเชิงลึกอยู่ในแผง NPC/เหตุการณ์ ผู้เล่นไม่ควรถูกบังคับให้อ่านค่าสเตตัสจำนวนมากเพื่อเข้าใจสถานการณ์

### 1.4 ไม่ใช้สีเป็นสัญญาณเดียว

สถานะทุกชนิดมีไอคอน รูปแบบเส้น หรือข้อความประกอบ เช่น อันตรายใช้สีแดงร่วมกับสัญลักษณ์เตือนและป้าย “เสี่ยงสูง”

### 1.5 ไม่สร้างความเร่งด่วนปลอม

ใช้ป้าย “ต้องตัดสินใจก่อนเหตุการณ์ถัดไป” เฉพาะเมื่อมี deadline จริง หลีกเลี่ยงตัวจับเวลานับถอยหลังที่สร้างแรงกดดันโดยไม่มีผลจำลองรองรับ

## 2. โครงสร้างข้อมูลและการนำทางหลัก

หน้าเกมหลักแบ่งเป็น 5 โซน:

1.  **แถบสถานะโลก:** ชื่อโลก บท/ฤดูกาล เวลาโลก สถานะการเชื่อมต่อ และข่าวสำคัญ

2.  **แถบนำทาง/รายการติดตาม:** แผนที่ ตัวละคร เหตุการณ์ เศรษฐกิจ พงศาวดาร และรายการ NPC ที่จับตามอง

3.  **พื้นที่ Constellation View:** แผนที่เชิงพื้นที่หรือแผนภาพความสัมพันธ์ซึ่งผู้เล่นคลิกตรวจสอบได้

4.  **แผงรายละเอียด:** แสดงข้อมูลพื้นที่/เหตุการณ์/NPC ที่เลือก โดยไม่ปิดแผนที่ทั้งหมด

5.  **แถบกิจกรรม:** ข่าวสารตามลำดับเวลา ปุ่มกรอง และตัวควบคุมการดูเหตุการณ์ย้อนหลัง

โครงสร้างการนำทาง

- **โลก:** Constellation View และแผนที่ภูมิภาค

- **ตัวละคร:** รายชื่อ NPC, ผู้ถูกจับตามอง และปาร์ตี้

- **เหตุการณ์:** วิกฤต ภารกิจ และความช่วยเหลือที่รอการตัดสินใจ

- **เศรษฐกิจ:** สต็อก ราคา การผลิต และเส้นทางขนส่งระดับชุมชน

- **พงศาวดาร:** ประวัติเหตุการณ์และสายเหตุ/ผล

ใน MVP ให้โลก/Constellation View เป็น landing page และให้ NPC ที่ติดตามปรากฏเป็นทางลัดบน sidebar

## 3. Constellation View: วัตถุประสงค์

Constellation View ไม่ใช่แค่ภาพดาวสวย แต่เป็นหน้าจอสำหรับอ่านสถานการณ์และเลือกว่าจะติดตามอะไร

ผู้เล่นต้องทำได้

- เข้าใจภูมิภาคและความเชื่อมโยงระหว่างสถานที่

- เห็น NPC/ปาร์ตี้สำคัญและกิจกรรมที่กำลังทำ

- เห็นเส้นทางการค้า ภัยคุกคาม และความสัมพันธ์ที่เกี่ยวกับเหตุการณ์

- คลิกจากสัญญาณบนแผนที่ไปยังแผงรายละเอียดที่เกี่ยวข้อง

- ส่งกลุ่มดาวไปจับตามอง NPC หรือเหตุการณ์ โดยไม่ย้าย/สั่ง NPC

- เปลี่ยนมุมมองโดยไม่สูญเสียบริบทหรือหลงตำแหน่ง

สิ่งที่หน้าจอนี้ไม่ควรทำ

- แสดงทุกเส้นความสัมพันธ์พร้อมกันจนกลายเป็นเส้นพันกัน

- ให้การลากดาวดูเหมือนผู้เล่นกำลังสั่งย้าย NPC

- เปิดเผยข้อมูลลับที่ตัวละครในโลกยังไม่รู้

- ใช้แผนที่เป็นจอเต็มโดยไม่มีข่าว/สถานะ/บริบท

- แสดงผลการกระทำของผู้เล่นอื่นแบบแข่งขันหรือกล่าวโทษโดยไม่จำเป็น

## 5. ภาพแผนที่และสัญญะ

### 5.1 โหนดสถานที่

แสดงเมือง หมู่บ้าน ป่า เหมือง และดันเจียนเป็นโหนดบนแผนที่เชิงพื้นที่แบบ stylized ไม่จำเป็นต้องเป็นแผนที่ภูมิศาสตร์แม่นยำ จุดประสงค์คือสื่อเส้นทาง เวลา และความเสี่ยง

แต่ละโหนดแสดง:

- ชื่อและชนิดสถานที่

- สถานะสั้น เช่น “สงบ”, “ขาดยา”, “ภัยระดับกลาง”

- ตัวบ่งชี้กิจกรรม/เหตุการณ์ หากมี

- ตัวบ่งชี้สต็อกหรือแนวโน้มเศรษฐกิจในเลเยอร์ที่เกี่ยวข้อง

### 5.2 เส้นทาง

รูปแบบเส้นสื่อสถานะ:

- เส้นทึบ: เปิดและเดินทางได้

- เส้นประ: มีความเสี่ยง/ข้อมูลไม่ครบ

- เส้นจาง: เส้นทางรองหรือไม่มีการเดินทางในช่วงนี้

- สัญลักษณ์ขบวน: มีสินค้ากำลังเดินทาง

- สัญลักษณ์เตือน: ถูกปิด/มีเหตุขัดขวาง

เส้นทางต้องมี tooltip ระบุระยะเวลาโดยประมาณและระดับความเสี่ยงที่ผู้เล่นทราบ ไม่อ้างว่าเป็นข้อมูลสมบูรณ์หากเป็นข่าวลือ

### 5.3 NPC และปาร์ตี้

แสดงเฉพาะ:

- NPC ที่จับตามอง

- NPC/ปาร์ตี้ในเหตุการณ์สำคัญ

- ปาร์ตี้ที่เกี่ยวกับวิกฤตหรือภารกิจที่ผู้เล่นติดตาม

ใช้ไอคอน portrait ขนาดเล็กบนโหนดหรือข้างเส้นทาง หลีกเลี่ยงการวางไอคอนประชากรทุกคนบนแผนที่

### 5.4 เส้นความสัมพันธ์

เส้นระหว่าง NPC แสดงเฉพาะเมื่อเปิดเลเยอร์ “ความสัมพันธ์” และเลือกบุคคลตั้งต้นแล้ว:

- เส้นบาง: ความสัมพันธ์ทั่วไป

- เส้นคู่/สัญลักษณ์หัวใจ/โล่/รอยแตก: ประเภทความสัมพันธ์ที่เด่น

- ลูกศร: ความสัมพันธ์หรือความรู้สึกไม่จำเป็นต้องเท่ากันสองทาง

- ซ่อนเส้นที่มีความสำคัญต่ำกว่า threshold และรวมเป็น “อีก 4 ความสัมพันธ์”

การแสดงทุกเส้นพร้อมกันเป็นค่าเริ่มต้นไม่เหมาะ เพราะจะรกและทำให้ผู้เล่นตีความผิด

## 6. เลเยอร์และตัวกรองบนแผนที่

แสดงปุ่มเลเยอร์หลัก 4 แบบ โดยเลือกได้ครั้งละหนึ่งเลเยอร์หลัก และเปิดตัวกรองย่อยได้

| เลเยอร์    | สิ่งที่เน้น                          | คำถามที่ตอบ                |
|-----------|---------------------------------|--------------------------|
| **โลก**   | สถานที่ เส้นทาง สถานะพื้นที่           | โลกเชื่อมกันอย่างไร?         |
| **ผู้คน**   | NPC ที่ติดตาม ปาร์ตี้ และเหตุการณ์      | ใครกำลังทำอะไร?           |
| **การค้า** | สต็อก/แนวโน้ม/ขบวนสินค้า/เส้นทาง     | ของขาดหรือกำลังเดินทางที่ไหน? |
| **ภัย**    | มอนสเตอร์ วิกฤต และความเสี่ยงเส้นทาง | จุดใดกำลังอันตราย?          |

ตัวกรองผู้คน: ติดตามอยู่ / บาดเจ็บ / กำลังผจญภัย / มีเหตุการณ์ / เป็นผู้นำปาร์ตี้  
ตัวกรองเศรษฐกิจ: อาหาร / ยา / วัตถุดิบ / สินค้าระหว่างทาง / จุดขาดแคลน  
ตัวกรองภัย: ระดับต่ำ–กลาง–สูง / ข่าวยืนยัน / ข่าวลือ

เปลี่ยนเลเยอร์แล้วตำแหน่งแผนที่ต้องคงเดิม ไม่ซูมหรือจัดโหนดใหม่โดยไม่แจ้ง

## 7. แผงรายละเอียดด้านขวา (Context Inspector)

แผงขวาเปลี่ยนเนื้อหาตามสิ่งที่เลือก: สถานที่ เส้นทาง เหตุการณ์ ปาร์ตี้ หรือ NPC

ลำดับเนื้อหามาตรฐาน

1.  **หัวเรื่อง:** ชื่อ ภาพ/ไอคอน และชนิดสิ่งที่เลือก

2.  **สถานะปัจจุบัน:** กำลังทำอะไร/เกิดอะไรขึ้น พร้อม timestamp ล่าสุด

3.  **เหตุผล/บริบท:** สาเหตุหลักที่ระบบบันทึกได้

4.  **ความเสี่ยงหรือแนวโน้ม:** แสดงเป็นระดับและความเชื่อมั่น

5. **ผลกระทบ:** ใคร/ที่ใดได้รับผลแล้วหรือจะได้รับผล

6. **การกระทำของกลุ่มดาว:** ปุ่มที่ใช้ได้และข้อจำกัด

7. **ลิงก์ต่อเนื่อง:** เปิดหน้าต่าง NPC เต็ม เปิดพงศาวดาร หรือดูเส้นทาง

พฤติกรรมของแผง

- คลิกที่โหนดครั้งเดียว: เลือกและเปิด inspector

- คลิกที่ NPC: inspector แสดง NPC แบบย่อ

- ปุ่ม “เปิดโปรไฟล์เต็ม”: เปิด NPC Detail Drawer/Modal

- ปิดแผงแล้วแผนที่ยังคงตำแหน่ง/ซูมเดิม

- มี breadcrumb เช่น <u>โลก \> ป่ารากเงิน \> ปาร์ตี้เรน่า</u> เพื่อกลับบริบท

## 8. แถบซ้าย: Navigation และ Watchlist

### 8.1 Navigation

ให้มีเมนูหลักไม่เกิน 5–6 รายการ เรียงตามงานที่ผู้เล่นทำบ่อย:

1. โลก

2. ตัวละคร

3. เหตุการณ์

4. เศรษฐกิจ

5. พงศาวดาร

มีสถานะ active ชัดและ badge จำนวนเหตุการณ์ที่ยังไม่อ่าน โดย badge ไม่ควรทำให้ผู้เล่นเข้าใจว่าต้องกดเข้าไปทันที

### 8.2 Watchlist

ส่วน “กำลังจับตามอง” แสดง NPC หลักได้ 1 คนตามกติกาพลังกลุ่มดาว พร้อมทางลัดตัวละครที่ปักหมุดไว้ (ไม่เพิ่มผลเชิงกลไก)

แสดงต่อรายการ:

- Portrait/สัญลักษณ์

- ชื่อ + สถานะหนึ่งบรรทัด

- จุดสถานะ เช่น บาดเจ็บ/เดินทาง/เหตุการณ์ใหม่

- เวลาที่อัปเดตล่าสุด

การปักหมุดหลายคนเป็นฟังก์ชัน UI เท่านั้น ไม่ควรทำให้พวกเขาได้รับพรหรือการปกป้องโดยอัตโนมัติ

## 9. แถบกิจกรรมและเหตุการณ์

### 9.1 รูปแบบรายการ

แต่ละเหตุการณ์มี:

- ไอคอนชนิดเหตุการณ์

- หัวข้อสั้นที่บอกผลหรือการเปลี่ยนแปลง

- บุคคล/สถานที่ที่เกี่ยวข้อง

- เวลาเกิดและเวลาที่เซิร์ฟเวอร์บันทึก

- ป้ายความสำคัญ: ปกติ / น่าสนใจ / วิกฤต

- สถานะอ่านแล้ว/ยังไม่อ่าน

### 9.2 ตัวกรอง

ทั้งหมด / คนที่ติดตาม / วิกฤต / เศรษฐกิจ / การผจญภัย / การแทรกแซงของกลุ่มดาว

### 9.3 การดูย้อนหลัง

การลาก timeline หรือเปิดเหตุการณ์เก่าเป็น **การดูประวัติย้อนหลังเฉพาะหน้าจอ** ไม่ใช่การย้อนเวลาโลกหรือยกเลิกผลลัพธ์ ต้องมีป้าย “กำลังดูข้อมูล ณ เวลา…” ชัดเจน และปุ่ม “กลับสู่ปัจจุบัน” ที่เห็นได้เสมอ

### 9.4 การรวมเหตุการณ์

เหตุการณ์เล็กที่เกิดซ้ำ เช่น ร้านค้ารับสินค้า ให้รวมเป็นสรุป “วันนี้ตลาดรับสินค้า 8 รายการ” ผู้เล่นคลี่ดูได้ เพื่อลด notification fatigue

## 10. หน้าต่าง NPC: เป้าหมายและรูปแบบ

## 11. เนื้อหาในหน้าต่าง NPC

### 11.1 Header

- portrait/อัตลักษณ์ภาพ

- ชื่อและอาชีพ/บทบาท

- ชุมชนต้นทางหรือสังกัด

- ป้ายจับตามอง/ปักหมุดส่วนตัว

- สถานะชีวิต: ปกติ บาดเจ็บ พักรักษา เดินทาง ไม่ทราบข่าว หรือเสียชีวิต

- ปุ่มปิดและปุ่มเปิดมุมมองความสัมพันธ์บนแผนที่

### 11.2 สถานะปัจจุบัน

แสดงสิ่งที่ผู้เล่นต้องใช้ตัดสินใจ ไม่แสดงค่าสถานะทุกค่า:

- กิจกรรมปัจจุบันและเป้าหมาย

- ตำแหน่ง/เส้นทาง

- สุขภาพแบบระดับและสถานะบาดเจ็บ

- ความเหนื่อยและเสบียง

- ความเสี่ยงของแผนปัจจุบัน

- เวลาที่ข้อมูลอัปเดต

ถ้ามีค่าตัวเลข เช่น ความคืบหน้า/ปริมาณเสบียง ต้องใส่หน่วยและไม่ใช้ความแม่นยำปลอม

### 11.3 เหตุผลและแรงจูงใจ

แสดง:

- เป้าหมายระยะสั้น

- เป้าหมายระยะยาว

- เหตุผลการตัดสินใจล่าสุด (1–3 ข้อ)

- ความต้องการเร่งด่วนที่ผู้เล่นควรรู้

- ข้อมูลที่ NPC ใช้ตัดสินใจ เช่น ข่าว/สต็อก/คำขอ

แยก “ข้อเท็จจริง” กับ “ความเชื่อ/ข่าวลือ” ด้วยป้าย เช่น <u>ยืนยัน</u>, <u>ข่าวลือ</u>, <u>คาดการณ์</u>

### 11.4 แท็บความสัมพันธ์

แสดงบุคคลที่เกี่ยวข้องมากที่สุด 3–5 คนก่อน พร้อมประเภทความสัมพันธ์และเหตุการณ์ที่ทำให้เปลี่ยน เช่น:

- ไว้ใจสูง — “ช่วยกันระหว่างภารกิจในเหมือง”

- เคารพปานกลาง — “ร่วมงานกันแต่มีความเห็นต่าง”

- คับข้องใจ — “แบ่งของรางวัลไม่เป็นธรรม”

ไม่ต้องเปิดเผยคะแนนลับเป็นเลขทุกค่าโดยค่าเริ่มต้น แสดงรายละเอียดเพิ่มเมื่อผู้เล่นเลือกโหมดวิเคราะห์

### 11.5 แท็บเศรษฐกิจ

เปิดเผยเฉพาะข้อมูลที่เกี่ยวข้องกับตัวละครและทราบได้:

- เงินส่วนตัว/เงินครัวเรือนเป็นช่วง หากตัวละครไม่เปิดเผยจำนวนแน่นอน

- อาชีพ รายได้ หรือสถานะการจ้างงาน

- อุปกรณ์และของจำเป็นที่เกี่ยวกับภารกิจ

- สินค้าที่ขาด/ต้องการซื้อ

- สัญญาหรือหนี้ที่มีผลต่อการตัดสินใจ

ไม่ควรแสดงเงินสดหรือทรัพย์สินทั้งหมดของ NPC ทุกคนเป็นข้อมูลสาธารณะ หากไม่มีเหตุในโลกให้รู้

### 11.6 แท็บบันทึก

แสดงเหตุการณ์สำคัญที่ตัวละครมีส่วนร่วม พร้อมตัวกรองและเส้นเหตุ/ผล เปิดจากรายการไปยังเหตุการณ์ในพงศาวดารได้

## 12. การกระทำจากหน้าต่าง NPC

### 12.1 วางตำแหน่งปุ่ม

วางปุ่มหลักไว้ใกล้สถานะ/เหตุผลที่เกี่ยวข้อง และทำแถบ action ด้านล่างติดตำแหน่ง (sticky) เมื่อเลื่อนดูรายละเอียด

ตัวอย่าง:

- **พยากรณ์:** แสดงเมื่อมีการตัดสินใจเสี่ยงที่ยังไม่เกิด

- **ส่งลาง:** แสดงเมื่อมีข้อมูล/เบาะแสที่ส่งให้ได้

- **ประทานพร:** แสดงเมื่อ NPC/ปาร์ตี้อยู่ในเหตุการณ์ที่รับผลได้

- **ของขวัญ:** แสดงเมื่อของขวัญถูกประเภทและผู้รับมีที่เก็บ/ใช้ได้

- **พิทักษ์:** แสดงเมื่อกำลังเดินทาง/ภารกิจที่ป้องกันได้

การกระทำที่ยังใช้ไม่ได้ให้แสดงเหตุผลใน tooltip หรือสถานะ disabled ที่อ่านได้ ไม่ซ่อนจนผู้เล่นไม่รู้ว่ามีความสามารถนี้

### 12.2 ขั้นยืนยันการใช้พลัง

คลิกปุ่มเปิด confirmation panel ที่ระบุ:

- ผู้รับ/เหตุการณ์ที่จะได้รับผล

- ต้นทุนและแต้มคงเหลือหลังใช้

- cooldown หลัง commit

- ผลที่คาดและขีดจำกัด

- ผลจากกลุ่มดาวอื่น/เพดานการสนับสนุน

- ปุ่มยืนยันและยกเลิกที่แยกชัด

ตัวอย่างข้อความ:

**ประทานพรแก่ปาร์ตี้เรน่า**  
ใช้ 25 อิทธิพล · เหลือ 37/100 · ใช้พรกับเหตุการณ์นี้ได้ 1 ครั้งต่อผู้เล่น  
เพิ่มขวัญกำลังใจและอาจเพิ่มโอกาสสำเร็จ ผลรวมจากกลุ่มดาวมีเพดาน และไม่รับประกันชัยชนะ  
<u>\[ยืนยันการประทานพร\]</u> <u>\[ยกเลิก\]</u>

ไม่มีการใช้พลังจาก double-click หรือกด Enter โดยไม่ตั้งใจ; หากเกิด network retry ต้องใช้ idempotency key เพื่อไม่หักแต้มซ้ำ

## 13. สถานะสดและการเปลี่ยนแปลงระหว่างเปิดหน้าต่าง

โลกออนไลน์เปลี่ยนได้ขณะที่ผู้เล่นกำลังอ่าน NPC panel จึงต้องป้องกันข้อมูลเก่าและการกดยืนยันผิดบริบท

สถานะที่ต้องรองรับ

- **สด:** อัปเดตล่าสุดทันเวลา

- **มีการเปลี่ยนแปลง:** แสดงแถบ “สถานะเปลี่ยนแล้ว” พร้อมสิ่งที่เปลี่ยน

- **ข้อมูลเก่า:** แสดงเวลาล่าสุดและปุ่ม refresh

- **เป้าหมายออกจากเหตุการณ์:** ปิดปุ่มพลังที่ใช้ไม่ได้และอธิบาย

- **กิจกรรมเสร็จระหว่างยืนยัน:** ขอให้ตรวจสอบสถานะใหม่ก่อน commit

- **เครือข่ายขาด:** ปิด action ที่เปลี่ยนโลก แต่ให้ดูข้อมูลที่แคชได้

การแจ้งโดยไม่รบกวน

- ไม่ refresh ทั้ง drawer จนเลื่อนตำแหน่งกลับด้านบน

- อัปเดตเฉพาะ component ที่เปลี่ยน เช่น สุขภาพ/สถานะ/เวลาล่าสุด

- เก็บข้อความที่ผู้เล่นกำลังอ่าน ไม่เปลี่ยนหน้าเอง

- หากมีเหตุวิกฤต ให้แสดงแถบแจ้งด้านบน ไม่ยึดหน้าจอเต็ม เว้นแต่ผู้เล่นเปิดยืนยันการแทรกแซงวิกฤต

## 14. การเปลี่ยนหน้าจอและการโต้ตอบ

### 14.1 การเลือกจากแผนที่

- hover: tooltip สั้น มีชื่อ สถานะ และเหตุผลเตือน

- click: เลือกและเปิด inspector

- double-click: ซูมเข้า/ศูนย์กลางแผนที่ที่โหนด (ไม่เปิด action ทันที)

- click NPC token: เปิด NPC drawer

- click event marker: เปิด event inspector; มีลิงก์ต่อไปยัง NPC ที่เกี่ยวข้อง

### 14.2 เมาส์/คีย์บอร์ด

- <u>Tab</u> ไล่โฟกัสตามลำดับ sidebar → แผนที่ → inspector → activity feed

- <u>Enter/Space</u> เลือกสิ่งที่โฟกัส

- <u>Esc</u> ปิด tooltip/confirmation ก่อน ปิด drawer เป็นลำดับถัดไป

- ปุ่มลูกศรเลื่อนเลือกโหนด/รายการที่อยู่ติดกันได้

- มี focus ring ชัดเจน

- ห้ามผูก action สำคัญกับ hover อย่างเดียว

### 14.3 ย่อขนาดหน้าจอ

แท็บเล็ต: sidebar ยุบเป็น icon rail, inspector เป็น drawer 40–50% ของความกว้าง  
มือถือ (ถ้ารองรับภายหลัง): แผนที่เต็มจอ มี bottom sheet สำหรับ NPC/สถานที่ และ action สำคัญอยู่ในแถบล่าง โดยไม่ซ้อนปุ่มแคบเกินไป

ยังไม่ควรเริ่มจากการออกแบบมือถือก่อน หากแพลตฟอร์มหลักเป็น PC เพราะแผนที่และการดูความสัมพันธ์ต้องการพื้นที่

## 15. สี ตัวอักษร และภาษาภาพ

### 15.1 แนวทางภาพ

- พื้นหลังสีกรมท่า/น้ำเงินดำ ลดลวดลายใต้ข้อความ

- จุดดาวและเส้นกลุ่มดาวเป็นสีอุ่น/ทอง ใช้กับความสนใจหรือพลังของผู้เล่น

- สีสถานะโลกแยกจากสีพลังกลุ่มดาว: หลีกเลี่ยงใช้ทองแทนอันตรายและความสำเร็จพร้อมกัน

- สีเตือนต้องมีระดับ: เหลือง/ส้ม/แดง พร้อม label ไม่ใช้แดงเต็มหน้าจอโดยไม่จำเป็น

- พื้นที่แผนที่มี contrast สูงพอให้เห็น node/เส้นทางบนจอขนาดเล็ก

### 15.2 Typography

- ชื่อ NPC และสถานะใช้ระดับตัวอักษรชัด

- ข้อความเหตุผลไม่เกิน 2–3 บรรทัดใน summary พร้อมปุ่มขยาย

- ตัวเลขทรัพยากรจัดแนวและใช้หน่วยเดียวกัน

- เลี่ยงตัวพิมพ์บางบนพื้นหลังมืดสำหรับข้อความหลัก

### 15.3 Motion

- เส้นแสงเคลื่อนช้าเมื่อมีการสนับสนุนกลุ่มดาว

- animation ของเหตุการณ์ไม่ควรซ่อนข้อมูลหรือบล็อกการคลิก

- ปรับ reduced motion ได้

- ไม่ใช้แสงกระพริบเพื่อแจ้งวิกฤต; ใช้สัญลักษณ์/ข้อความแทน

## 16. การตั้งค่าการแจ้งเตือน

ผู้เล่นเลือกชนิดเหตุการณ์ที่อยากได้รับแจ้ง:

- NPC ที่จับตามองเปลี่ยนเป้าหมาย/บาดเจ็บ/กลับถึงเมือง

- วิกฤตชุมชนเปลี่ยนระดับ

- การเดินทาง/ภารกิจสำเร็จหรือล้มเหลว

- ราคาหรือสินค้าจำเป็นเปลี่ยนระดับสำคัญ

- กลุ่มดาวอื่นสนับสนุนเหตุการณ์ที่ติดตาม

- ผลของพลังที่ตนใช้สำเร็จ/หมดอายุ

ช่องทางแจ้งเตือนภายนอก (push/email) เป็นตัวเลือกภายหลัง ไม่ควรส่งทุกเหตุการณ์ย่อย และต้องมี quiet hours/ระดับความถี่

## 17. ความเป็นส่วนตัวและการแสดงการกระทำกลุ่มดาวอื่น

ข้อมูลที่แสดงได้

- จำนวนกลุ่มดาวที่สนับสนุนเหตุการณ์ หากเป็นข้อมูลสาธารณะ

- หมวดผลที่ได้รับ เช่น “มีการสนับสนุนด้านกำลังใจแล้ว”

- ชื่อกลุ่มดาวเฉพาะเมื่อผู้เล่นเลือกให้แสดงต่อสาธารณะ

- ประวัติผลพลังที่มีผลต่อโลกในพงศาวดาร

ข้อมูลที่ไม่ควรเปิดโดยค่าเริ่มต้น

- ยอดอิทธิพลคงเหลือของผู้เล่นคนอื่น

- รายละเอียดการล็อกอิน/กิจกรรมของผู้เล่นคนอื่น

- ข้อมูลบัญชีหรือประวัติส่วนตัว

- ชื่อจริง/ข้อมูลนอกเกม

วัตถุประสงค์คือช่วยให้ร่วมมือได้โดยไม่สร้างแรงกดดันหรือการตามรังควาน

## 18. สถานการณ์ UI ที่ต้องทดสอบ

A. เปิดแผนที่แล้วมีวิกฤตใหม่

แถบเหตุการณ์เด่นขึ้น แผนที่ไม่กระโดดเอง ผู้เล่นเลือกคลิกไปยังพื้นที่หรือปิดแจ้งได้

B. NPC ที่เปิดดูได้รับบาดเจ็บระหว่างอ่าน

Drawer คงตำแหน่งเดิม แสดงสถานะเปลี่ยนเป็นบาดเจ็บพร้อมเหตุการณ์ที่ทำให้เกิด ปุ่มพลังถูกอัปเดตตามเงื่อนไข

C. ผู้เล่นกดใช้พลังขณะมีคนอื่นสนับสนุนพร้อมกัน

เซิร์ฟเวอร์ตรวจเพดานแบบ atomic; หากรับได้แสดงผลใหม่ หากเต็มแล้วแสดงเหตุผลโดยไม่หักแต้ม

D. ผู้เล่นออฟไลน์กลับมา

เปิดหน้า “สรุปตั้งแต่ครั้งล่าสุด” มีเหตุการณ์สำคัญ 3–5 รายการ รายละเอียดเพิ่มเติมขยายได้ และปุ่ม “กลับสู่แผนที่ปัจจุบัน”

E. ข้อมูลข่าวลือไม่ตรงกับผลจริง

แสดงป้ายความเชื่อมั่นก่อนใช้พลังและบันทึกแหล่งข่าวหลังเกิดเหตุ ไม่กล่าวโทษ NPC ว่าโง่เพราะใช้ข้อมูลเท่าที่มี

F. จอแคบหรือ sidebar เปิดอยู่

แผนที่ยังคลิกได้ แผงไม่ทับปุ่ม action สำคัญ และมีวิธีปิดด้วยปุ่ม/คีย์บอร์ด

## 19. เกณฑ์ยอมรับ UI/UX สำหรับต้นแบบ

1. ผู้ทดสอบหาสถานะของ NPC ที่จับตามองได้ภายใน 5 วินาที

2. ผู้ทดสอบอธิบายได้ว่า NPC กำลังทำอะไรและเหตุผลหลักคืออะไร

3. ผู้ทดสอบเห็นต้นทุนและ cooldown ก่อนยืนยันการแทรกแซงทุกครั้ง

4. ไม่มีการใช้พลังจากการคลิกแผนที่โดยไม่ผ่าน confirmation

5. ผู้เล่นแยก “หยุดดูย้อนหลัง” ออกจาก “หยุดโลก” ได้ชัดเจน

6. เมื่อข้อมูลอัปเดตสด หน้าต่างไม่กระโดดหรือเปลี่ยนบริบทโดยไม่ตั้งใจ

7. ผู้เล่นเปิดดูความสัมพันธ์และกลับแผนที่ได้โดยไม่หลงตำแหน่ง

8. ข้อมูลเตือนใช้ข้อความ/ไอคอนร่วมกับสี

9. ผู้เล่นที่ไม่ได้เข้าเกมระหว่างเหตุการณ์เข้าใจสิ่งที่เกิดขึ้นจากสรุปย้อนหลัง

10. ผู้เล่นใหม่ใช้การจับตามองและอ่านเหตุผล NPC ได้โดยไม่ต้องอ่านคู่มือยาว

## 20. ลำดับสร้าง UI ที่แนะนำ

1. ทำ wireframe สีเทาของแผนที่ + sidebar + inspector ก่อนลงภาพตกแต่ง

2. ทดสอบ task flow: เลือก NPC → เข้าใจเป้าหมาย/ความเสี่ยง → ใช้พลัง → อ่านผล

3. ใส่ตัวอย่างข้อมูลเศรษฐกิจและเส้นทางเพื่อทดสอบความหนาแน่น

4. ทำ live update mock เพื่อดูว่าหน้าต่างไม่กระพริบ/กระโดด

5. ทดสอบที่ 1280×720 และ 1440×900 ด้วยข้อมูลจริงปริมาณสูง

6. ปรับ contrast และคีย์บอร์ด/การเข้าถึง

7. ค่อยลงสี ภาพดาว เส้นแสง และ motion

**หลักจัดลำดับ:** ความอ่านเข้าใจของสถานะและการกระทำมาก่อนความอลังการของฉากดวงดาว
